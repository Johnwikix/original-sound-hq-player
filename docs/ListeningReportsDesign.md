# 听歌报告设计

2026-11-27 · 设计稿

## 1. 方案摘要

在现有「统计」页增加「听歌报告」入口。用户可以按自然年或自然月回看有效收听时长、播放次数、活跃天数、常听歌曲与歌手，并把当前所看的报告导出为一张竖版 PNG。此稿把需求中的「阅读报告」理解为「月度听歌报告」。

年度和月度复用同一套取数口径和海报模板。年度用各月趋势回顾全年，月度用每日分布呈现习惯。既有播放历史可直接按期查询，首版无需改库或采集新数据。

## 2. 现有能力与参考

- **现有播放历史**按会话保存 UTC 开始、结束时间、时长、歌曲 ID 和标签快照，并已对开始时间建索引。当前只保存已结算、收听量达到曲长至少 50% 的会话，未入库的临时播放也不写入。已入库的 WebDAV 曲目在确认开始播放后也走同一会话采集。时长按播放进度差累计、按曲长封顶，向前跳播可能计入。库内歌曲显示的累计播放次数由另一条链路记录开始次数，无法补回旧时期的日期与时长。见 [PlaybackHistory.cs](../Model/Stats/PlaybackHistory.cs#L12)、[会话阈值与记录](../Services/PlaybackStatsService.cs#L22)、[累计播放次数](../Services/PlaybackStatsService.cs#L106)、[进度和写库](../Services/PlaybackStatsService.cs#L148)、[历史表及索引](../Services/MusicDatabaseService.cs#L137)、[WebDAV 会话入口](../Services/RemotePlaybackService.cs#L260)。

## 3. 桌面交互

1. 「统计」标题行右侧增加「听歌报告」。打开主窗口内的报告子页，可返回统计页。
2. 页头放「年度」「月度」切换、年份选择器、月度模式下的月份选择器，以及「刷新」「导出总结图」。首次默认打开本年，切换月度时默认本月。在同次浏览里记住两个模式各自选择的期间。
3. 历史选择从本库最早可识别的已保存记录所在周期延伸至当前周期，中间空白期间可查，未来期间不可选。首次查看时若本期为空且有更早结果，空状态提供「查看最近有记录的年度／月份」。
4. 从上到下展示大字标题与实际统计范围、三项核心指标、期间趋势、常听排行，滚动查看。宽窗口中趋势与排行可并排，窄窗口单列。排行和趋势同时提供文本标签，键盘可完整操作。
5. 首次进入、切换期间和点击刷新时生成报告。已结算的新数据在下一次生成时计入。预览使用打开时的报告快照，报告跨月或跨年切换由用户选择明确的日期。

| 内容 | 年度听歌报告 | 月度听歌报告 |
| --- | --- | --- |
| 标题 | 2026 年度听歌报告 | 2026 年 11 月听歌报告 |
| 共同指标 | 有效收听时长、有效播放次数、活跃天数 | 有效收听时长、有效播放次数、活跃天数 |
| 期间趋势 | 1 至 12 月有效播放次数柱图，可突出播放最多的月份 | 当月自然日历热度图，按有效播放次数着色，可突出播放最多的一天 |
| 报告排行 | 歌曲和歌手各最多 5 项 | 歌曲和歌手各最多 3 项 |

只有一个有记录的趋势分组或最高值并列时省略「播放最多的月份／日期」文案，图表仍展示实际结果。首版提供可滚动的静态报告和一张可分享的总结图。动画故事、人格分类、年度歌单、跨端导入和分享渠道集成留待后续单独评估。

## 4. 自然周期与统计口径

- **区间**。采用 Windows 本地时区。自然年从 1 月 1 日零时到次年 1 月 1 日零时，月度从当月 1 日零时到次月 1 日零时。起点含，终点不含。当前周期以本次查询时刻为上限，页面和图片标注「进行中 · 截至……」及本地时区。历史周期展示完整日历区间和本地时区。
- **会话归属**。整条会话按开始时刻进入一个期间和一个本地日。跨零点的一次播放只在起播所在日计入，跨月或跨年也同理。已有行只有总量和起止点，期间拆分无法精确恢复暂停、跳播和变速。时区变更后按新时区重新生成，已保存 PNG 保持生成时的日期与时区。日期按本地日逐日建立边界再转 UTC，避免假设每天固定 24 小时。
- **旧版兼容**。使用已保存的 `PlaybackHistory` 记录，按当时采集条件保留历史。没有记录只能显示「此期间无已保存的有效播放」。每期可提示「仅依据此曲库保留的播放记录」，库最早一条记录处于本期时显示其日期，避免把之前缺少记录的时段描述成未收听。累计 `Music.PlayCount`、Last.fm、其他设备的记录和正在播放但尚未结算的会话均不纳入。

| 指标 | 首版规则 |
| --- | --- |
| 有效播放次数 | 所选周期内已保存的会话条数。同一首反复播放可计多次，单位用「次」。当前版本的入库门槛是至少达到曲长 50%。 |
| 有效收听时长 | 汇总这些会话已保存的时长，每次最多计曲长，不重新按最近版本补算。按小时、分钟显示，少于一分钟时用秒。口径说明注明按播放进度累计，快进或向前拖动可能计入。 |
| 活跃天数 | 至少有一次有效播放开始的本地日期数，月历、年度柱图与总数使用同一批会话。当前周期未来日期呈现为未到。 |
| 常听歌曲 | 延续现有歌曲身份优先顺序，以当前歌曲归属、播放时归属、音频版本 ID 依次兜底。缺失 ID 的旧记录可按保存的标题、作者、专辑分组。优先用历史文本展示，曲库删除后仍可保留历史条目。 |
| 常听歌手 | 用历史会话中的作者标签原样分组。合唱标签按一条展示。空作者的记录仍计入总量，歌手榜略过空标签。 |
| 排行顺序 | 先按次数降序，再按累计时长降序，最后按稳定的组标识确定顺序。合并多版本造成标题不同，优先使用该期最近一条有标题的历史会话作为展示名。 |

查询失败呈现错误与「重试」。全库无历史时保留入口并解释数据来源，空报告禁用导出。只有少量记录时仍可查看并导出，只渲染已有条目；缺失歌手或封面时缩减版式或使用默认图形。

## 5. 总结图设计

采用固定 **1080 × 1350（4:5）PNG**。顶部放日期、报告类型和进行中标记，中部大字展示有效收听时长，旁边是有效播放次数与活跃天数。下部放当期最常听的三首歌及第一名歌手。使用原音主题色、简洁唱片纹理和可选的第一名歌曲封面。没有封面或离线时使用同样版式的默认唱片图形。页脚标明统计期间、使用时区与「仅统计本机保存的有效播放」。图片只含报告内容、歌曲和歌手名及应用标记，避免包含文件路径、设备名、账号和文件标签等信息。

- 点击「导出总结图」在主窗口内打开卡片预览，确认后由 Windows 保存对话框选择位置。默认文件名示例为 `OriginalSound-Listening-2026.png` 或 `OriginalSound-Listening-2026-11.png`。
- 基于预览生成专用卡片的位图。卡片在主窗口的 WinUI 可视树内可见并完成布局，导出以卡片本身为边界。图像的画幅由卡片决定，适配窗口宽度和 DPI。使用本地已可用的封面或默认图形，等待最终资产就绪后才允许导出。使用捕获后实际像素尺寸检查结果。[Microsoft 的 RenderTargetBitmap 限制](https://learn.microsoft.com/en-us/windows/windows-app-sdk/api/winrt/microsoft.ui.xaml.media.imaging.rendertargetbitmap.renderasync?view=windows-app-sdk-2.0) · [WinUI 文件保存对话框](https://learn.microsoft.com/en-us/windows/apps/develop/files/pickers-save-file)
- 保存按钮单次执行，取消后返回预览。先在目标目录写好临时 PNG，再提交到选定路径。需要覆盖时使用文件系统支持的替换操作，失败时保留原文件，清理临时文件并提示重试或另存。保存成功后展示位置。

## 6. 接入边界

- **数据查询**。复用 `PlaybackStatsService` 现有会话表、索引、聚合及歌曲身份规则。报告按 `StartedAt >= 起点 AND StartedAt < 终点` 取数，并在同一个短读快照内得到总量、排行、分布和历史起点，防止结算中的新会话只出现在部分区块。Windows 时区与查询截止时间随请求固定，日期分桶使用同一组本地边界。SQL 使用现有索引，只返回聚合及限量排行，不把整年明细载入 UI。旧统计筛选仍使用自己的范围语义。首版数据只读，无迁移、定时生成和历史报告缓存。
- **视图状态**。报告 ViewModel 拥有当前模式、周期、加载、重试和导出命令。更换期间或离页时取消等待、失效旧结果，UI 线程才发布绑定状态。导出锁定与预览相同的数据和封面结果，离页和退出时收尾在途任务与临时文件；抓取 UI 在 UI 线程执行，后续编码与写盘避开 UI 热路径。报告按需加载，避免启动或播放时增加工作。
- **WinUI 约束**。使用 `x:Bind`。报告正文、日期单位、空态、错误、按钮和海报需要覆盖现有七套语言资源，代码取词使用独立资源键。模板若需调用共享命令，按现有命令模式接入。若后续增加分段采集或历史重写，按 `LibraryDatabaseMigration.OpenAsync` 和版本规则另行评估。

## 7. 实现后验收

| 场景 | 通过标准 |
| --- | --- |
| 自然周期 | 用月底、年末、闰日、夏令时、切换时区和精确零点的隔离历史验证无漏算、重算。跨年会话结算后只进入起播年。固定时区和时间时，历史月份的次数合计等于对应年度。 |
| 旧库和少量数据 | 读旧版正常建库后的已有历史。用空期间、单条记录、缺失标签、曲目删除、同曲多版本和正向跳播记录验证文案、榜单、时长及海报降级。默认播放统计口径可与报告同一边界手工对账。 |
| 请求与生命周期 | 快速切换月份、并发结算、切到空状态、失败后重试、导出时退出。过期结果不发布，报告与图片使用同一份快照，取消或失败时预览可恢复且原文件完好。 |
| WinUI 发布 | 使用全新输出目录进行 Release/x64 剪裁发布，实际打开发布产物测试入口、绑定、本地化、长歌名、导航、高清缩放、图片尺寸和保存流程。打开 PNG 检查完整性、文字和遮罩，覆盖无封面和覆盖保存。查询计划确认使用开始时间索引，并记录有代表性的大库延迟。 |

### 2026-11-27 实现验证

- 主程序在新输出目录完成 Release/x64 剪裁发布。检查发布程序集中的统计入口、XAML 绑定连接器与导出命令，并核对发布资源及七语言源文件。运行验证从同版剪裁的 WinUI 回归启动，使用隔离曲库。系统文件选择器用回归提供的返回值覆盖取消、路径失败和写入成功。
- 实际 WinUI 报告覆盖年度、月度、快速选期、空期间和最近记录。150% 显示缩放下捕获并重新解码 1080 × 1350 PNG，另验证编码补足分数缩放取整、覆盖保存和退出取消。
- Windows x64、.NET 11、24 万条互异歌曲和歌手且时间戳乱序的记录，预热后八次全年查询中位数 2.57 秒，最大 2.64 秒，查询线程托管分配最大 9,672 字节。三条聚合查询均命中开始时间索引。用发布版 SQLite 单独执行同样排行语句，SQLite 跟踪的原生分配高水位为 4,579,888 字节，关闭连接后回到零。
