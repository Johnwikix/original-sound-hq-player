# 首页与本地音乐推荐方案

日期：2026-10-28

首版采用基于曲目标签和个人收听记录的内容推荐，结合时间衰减、流派多样性和少量曲库探索。推荐计算全部在本地完成，不需要账号、云端模型或音频特征扫描。首页接入现有 NavigationView，使用 Microsoft Store 风格的大幅精选轮播和横向内容栏，新安装默认进入首页。

本方案作为首页实现依据。流派参与偏好匹配与多样性排序；没有流派时只忽略该维度，不过滤歌曲。精选轮播按用户要求在项目内自实现，不依赖 DevWinUI 的 StoreCarousel。

两个接入陷阱必须在实现中处理：

- `MainPage.xaml.cs:294` 使用 `MenuItems[1]` 选择音乐库。新增首页后应按 Tag 查找导航项，同时排查其他固定索引。
- `Services/MusicCommands.cs:20` 根据 `AppData.CurrentPage` 推导播放队列，而该字段主要描述音乐库子页。首页不能直接调用这个会隐式选队列的入口，必须明确传入当前推荐集合，再进入已有 PlaybackCoordinator。

另一个数据口径限制是 `Music.CreateTime` 来自文件创建时间，不是加入曲库的时间。首版不把它包装成“最近加入”；如后续需要该栏目，应增加独立的导入时间并定义旧库回填规则。

## 算法比较与选择

以下是针对单用户本地曲库和当前数据条件的工程选型，不代表通用效果排名。

| 方案 | 适配情况 | 首版取舍 |
| --- | --- | --- |
| 收藏、次数、随机等规则 | 无需训练，冷启动容易；单独使用时容易变成排行榜或随机播放 | 用作基线、探索和兜底 |
| 标签内容推荐 | 依靠艺术家、流派、专辑、年代和个人行为，无需其他用户数据；效果受标签质量限制 | 作为主算法 |
| 基于会话的共现或转移统计 | 可以从本人的播放序列学习关联；但顺序播放专辑会制造强共现，现有历史又缺少未达标会话 | 后续在行为数据足够时评估 |
| ALS、BPR 等协同过滤 | 常规训练依赖足够的用户与物品交互；本项目没有跨用户矩阵，歌曲也没有统一外部 ID | 首版不引入 |
| 音频特征或向量推荐 | 能补足标签，支持声学相似；需要特征提取、模型或额外缓存与任务生命周期 | 作为独立后续功能评估 |
| 上下文老虎机 | 能随反馈调整探索，但需要曝光、选择和奖励定义，当前尚无这些记录 | 首版用固定探索配额即可 |

内容推荐无需其他用户的数据，但容易反复推荐已有兴趣，因此需要显式加入探索与多样性重排。依据：[Google 内容推荐](https://developers.google.com/machine-learning/recommendation/content-based/basics)、[内容推荐的优缺点](https://developers.google.com/machine-learning/recommendation/content-based/summary)、[协同过滤](https://developers.google.com/machine-learning/recommendation/collaborative/basics)。音频、元数据等内容层次以及冷启动、多样性与效率之间的取舍，可参考[音乐内容推荐综述](https://arxiv.org/abs/2107.11803)。

推荐管线采用“候选生成 → 评分 → 多样性重排”，与 [Google 推荐系统架构](https://developers.google.com/machine-learning/recommendation/overview/types)的阶段划分一致；具体参数由本项目验证。

### 偏好与评分

1. 使用最近 90 天的达标历史建立艺术家、流派、专辑和年代偏好；有效收听比例越高，贡献越强。同一首歌反复播放的贡献采用饱和函数，避免单曲循环压倒整个偏好。
2. 给近期行为更高权重，使用 `1 / (1 + 距今天数 / 30)` 的双曲衰减，30 天前的单次信号为今天的一半。SQLite 基础算术即可计算，不依赖额外数学扩展。收藏提供稳定的正向信号。没有达标记录或 PlayCount 很低不代表不喜欢。
3. 艺术家拆分复用 ArtistHelper 和现有分隔符设置；多艺术家、多流派分摊一条记录的贡献，避免标签越多权重越大。过滤未知艺术家、未知专辑及空标签，不把占位文字变成兴趣。
4. 内容匹配建议起始权重：艺术家 45%、流派 30%、专辑 15%、年代 10%。缺失维度不产生负分；仅按有效维度计算，并按可用信息量控制置信度，避免只有一个标签的歌曲因重新归一化获得虚高分。
5. 综合内容匹配、达标重听强度、收藏和探索分排序。推荐理由来自实际贡献信号，例如“你常听这位艺术家”“来自你收藏的流派”；只有年代接近时不能解释成音色相似。

时间影响音乐偏好的研究可参考[时间感知音乐推荐](https://arxiv.org/abs/2008.11432)。90 天窗口、30 天衰减尺度和上述权重是初始产品参数，不是该论文给出的最优值。

### 流派与多样性

- 流派同时参与“合不合口味”和“整栏是否单一”的判断。多流派按集合处理，忽略空值及未知占位值，保守拆分明确分隔符，避免破坏完整流派名称。
- 通用“为你推荐”栏先尝试同一艺术家最多 2 首、同一专辑最多 1 首；专辑身份使用有效的专辑艺术家与专辑名组合，缺失时回退到曲目艺术家，避免同名专辑互相挤占。
- 在候选充足时减少连续的相同流派，并限制单一流派占满列表。首版使用计数和软惩罚，不预计算全库歌曲两两相似度。
- 每批约 20% 的位置用于探索少听、未形成强偏好的曲目，优先补充不同艺术家和流派。极小曲库或单流派曲库逐级放宽限制，不复制歌曲凑数。
- 未知流派不参与流派配额，也不被视为同一种流派；通过艺术家和专辑维度保持多样性。已知流派少时不要求强行凑齐多个流派。
- “常听回顾”“某张专辑”有明确主题，不机械套用通用栏的全部限制。通用栏之间尽量去重，主题栏可以重现符合主题的歌曲。

首版用上述约束重排即可。若后续需要更精细的相关性与新颖性权衡，可以只对有限候选使用 [MMR](https://www.cs.cmu.edu/afs/cs/Web/People/jgc/publication/MMR_DiversityBased_Reranking_SIGIR_1998.pdf)；该方法来自信息检索，其对本播放器的收益需要单独评估。

### 冷启动与刷新

有收藏而没有历史时，以收藏建立初始标签偏好；两者都没有时，展示按艺术家、专辑和已知流派分散的“探索曲库”，不假称已了解用户喜好。标签很少时退回分散采样，曲目仍可被推荐。

同一天、同一曲库和同一偏好版本的结果保持稳定，反复进入首页不重新洗牌。“换一批”仅切换当前候选批次，不触发扫描。播放选曲、历史结算和收藏只标记下次输入过期，点击“换一批”或重新进入首页时应用，避免操作中的卡片移动、封面闪烁和滚动位置重置。这类通知也不使在途刷新作废后立即重算。曲库、标签、分隔符和来源可用性变化继续合并刷新；内容相同时保留原栏目及主题对象。离开页面后不维持刷新工作，不用每秒定时重算。

## 首页布局与交互

保留现有 NavigationView、搜索框、标题栏和底部播放控件。导航顺序建议为：首页、音乐来源、音乐库、歌单、统计、设置。首页标题与“换一批”放在滚动区外的固定行；轮播与推荐栏目在其下方滚动。首页不嵌入音乐库内部的歌曲、专辑、艺术家、文件夹 SelectorBar。

```text
现有侧栏         首页                                  换一批
                ┌─────────────────────────────────────────┐
                │ 精选轮播：今天想听什么                    │
                │ 标题、推荐缘由、播放按钮   封面主图与侧图  │
                └─────────────────────────────────────────┘
                为你推荐／探索曲库     歌曲卡片横向排列
                最近常听               紧凑歌曲或专辑卡片
                换个流派听听           不同已知流派的曲目
现有底部播放条  当前曲目、进度、播放控制、音量
```

| 区域 | 内容 | 行为 |
| --- | --- | --- |
| 精选轮播 | 最多 3 个由本地曲库生成的主题入口，如“为你精选”“熟悉旋律”“换个流派” | 主按钮播放该主题快照；空主题不展示。没有历史时改为探索主题。 |
| 为你推荐 | 建议每批 12 首，展示封面、标题、艺术家和简短理由 | 点击卡片进入对应曲目或详情；显式播放按钮从该曲目开始播放本栏快照，支持收藏和加入队列。 |
| 最近常听 | 从达标历史中聚合的近期常听曲目 | 这是历史回顾栏目，不暗示记录了所有短暂播放，也不承诺断点续播。 |
| 换个流派听听 | 相对常听流派不同、且有实际标签依据的候选 | 有足够标签时出现；不足时省略，探索内容仍通过通用栏呈现。 |

歌曲卡片的点击、播放按钮和右键菜单需要与现有卡片语义统一；首版不新增独立详情窗口。“换一批”和推荐更新只改变展示，用户点击播放时才替换 SequentialPlayingList，保留现有随机、顺序、循环规则与选曲代次机制。已经开始播放的推荐队列不随后台重算变化。

首页按全部已入库曲目生成内容，不继承音乐库页残留的搜索词或来源筛选。现有搜索框提交查询时进入音乐库结果页并同步选中导航项，不能在首页输入后只悄悄修改隐藏的曲库状态。

普通卡片使用现有主题资源、封面和悬停方式，并在操作按钮下预留 24px，避免横向覆盖式滚动条侵入按钮。爱心沿用现有红色图标约定；加号通过悬停提示明确表示“加入当前播放队列”。“换一批”使用无边框、主题强调色前景按钮。

轮播按 DevWinUI StoreCarousel 的外观实现：左侧满幅封面、渐隐叠字和随图片取色的动作按钮，右侧一大两小的三图拼贴，底部圆点分页，悬停或键盘聚焦时显示圆形翻页按钮。主图约 1.22:1，拼贴使用略宽的大图与接近方形的小图，避免专辑封面被裁成长条；图片按原比例填满并显式居中裁切。保留圆角与阴影，窄窗主图保持比例，拼贴移至下方成为左大图和右侧上下两图。缺封面使用统一占位图；大字体、高对比度和键盘操作必须可用。

### StoreCarousel 接入判断

[官方文档](https://ghost1372.github.io/DevWinUI/controls/storeCarousel/index)和 [Gallery 示例](https://github.com/ghost1372/DevWinUI/blob/28d9f74fc1ad86d6597b6ad43b6122e52a1b49aa/dev/DevWinUI.Gallery/Views/Pages/Composition/StoreCarouselPage.xaml)提供大图、标题、说明、动作按钮、三张侧图、分页和自动轮播，适合首页精选区。

本机 DevWinUI 10.8.0 的 NuGet 元数据指向提交 `28d9f74fc1ad86d6597b6ad43b6122e52a1b49aa`。该版本的[控件源码](https://github.com/ghost1372/DevWinUI/blob/28d9f74fc1ad86d6597b6ad43b6122e52a1b49aa/dev/DevWinUI/Controls/Win2DAndComposition/StoreCarousel/StoreCarousel.cs)有几个直接影响首页集成的约束：

- ItemsSource 接收 IList 并复制到内部列表，不能依赖 ObservableCollection 原地变化自动更新轮播。
- 图片通过 URI 字符串加载，需要接入现有封面缓存或有限的本地展示资源，不能直接把任意 ImageSource 当作已支持。
- Unloaded 会停止并清空计时器；重新加载、重复应用模板和异步换图必须做原生 UI 验证。
- 动态替换列表时的索引、空列表、多个主题使用相同封面的文字刷新，都需要单独验证，不能只看静态 Gallery 成功。

最终采用项目自有 `FeaturedCarousel`，参照上述版本的布局比例、三图拼贴、叠字、圆角阴影、圆点分页和切换动效，保留 MIT 许可与来源说明至 `Libraries/DevWinUI/LICENSE-StoreCarousel.txt` 并随构建输出。主内容和拼贴都通过通用模板接入，支持按钮与方向键翻页、集合通知、动态替换和索引钳制，没有自动轮播计时器；首页不使用 DevWinUI 控件，未新增包依赖。

封面由 `MusicCoverControl` 直接把规范 Music 交给 `CoverLoadQueue`，沿用本地或远端原图读取、去重、WIC 和磁盘像素缓存。主图、拼贴、歌曲卡片分别请求 800、400、150px；共享请求键区分尺寸，解码最长边限制为 2048px，避免极端竖图放大占用。边缘取色直接采样已解码像素，不重复打开图片。每个消费者独立拥有并释放 SoftwareBitmapSource，卸载时取消；换图完成前保留旧图。

标题、说明与播放按钮分别使用缓存的滑入、淡入和轻微缩放动画，依次延迟 0/60/120ms；即使主题共用封面也重新播放文本动画，图片加载完成只触发独立的缩放淡入。快速切换停止旧动画并回到新主题，卸载重置，关闭系统动画时直接显示最终状态。翻页按钮以原生透明度和缩放过渡显隐，隐藏时关闭指针命中，保留键盘聚焦入口。

`CarouselLighting` 依据 [Composition Lighting](https://learn.microsoft.com/en-us/windows/apps/develop/composition/composition-lighting) 使用环境光维持封面原亮度。整组封面复用一盏聚光处理鼠标/笔跟随与按压扩散，不按卡片叠加非环境光；扩散、淡出和回到悬停的状态均写入合成关键帧，无完成回调或后台计时器。指针表达式在合成线程跟随，不逐帧从 UI 线程更新坐标；触控使用事件位置。指针移动或离开时重新接管聚光。轮播显式持有光源、表达式和动画，卸载解除目标及订阅并释放，重入重新建立，不增加图片读取链路。

## 空库与其他页面状态

| 状态 | 页面呈现与恢复入口 |
| --- | --- |
| 尚未完成数据库加载 | 显示有限的加载占位；确认库为空前不闪现“添加音乐”。 |
| 已加载且无音乐 | 与现有曲库空态一致：音乐图标、“从你的音乐开始”、说明、添加文件夹按钮、拖入文件夹提示；保留首页导航和底部播放条，不展示空轮播。 |
| 空库正在导入 | 复用 AddFolderViewModel 与 LibraryOperationGate 的忙碌状态；首批曲目到达后渐进呈现探索内容，不等整次扫描结束。 |
| 有音乐但无偏好 | 显示探索曲库和冷启动主题；不显示空的最近常听栏。 |
| 已知来源离线且无可用候选 | 显示检查音乐来源的提示，区别于空库；不通过首页逐曲 File.Exists 或联网探活。用户手动播放仍由现有服务重试。 |
| 标签或封面缺失 | 保留歌曲，使用已有字段和占位封面；不显示缺乏依据的推荐理由。 |
| 推荐计算失败 | 保留已有快照，提供重试；首次失败可显示曲库探索或轻量错误态，不伪装成没有音乐。 |
| 刷新时离开页面或退出 | 取消页面消费、拒绝迟到结果、停止图片与轮播；服务退出等待实际在途工作结束。 |

WebDAV 已入库曲目只使用现有索引和运行时可用性信息参与推荐，不因首页加载下载音频或读取远端标签。已知离线且无缓存的曲目不占用主要播放推荐位；音乐来源页继续承担连接与重试管理。纯本地曲库不产生推荐网络请求。

## 启动页与兼容性

- 新安装、没有设置记录时，使用 `SaveSettings.CreateForNewUser()` 创建 Home 默认值；运行时默认同样为 Home。`SaveSettings.DefaultEntry` 的反序列化默认仍为 AddFolder，以兼容缺少旧 `DefualtEntry` 字段的已有配置。
- 设置的“默认入口界面”加入首页，其他入口继续可选；未知或失效的入口值回退到 Home，并同步导航选中项。
- 升级时保留已有有效启动页，包括 AddFolder。当前没有“用户主动选择”的标记，不能判断旧值是否只是沿用默认，因而不自动覆盖。
- 页面导航不等于播放行为：首页不会自动开始播放，也不会覆盖恢复的播放队列。
- 首页仍受现有启动协议和生命周期控制，推荐计算不加入启动就绪的必等链路。

## 职责与性能约束

| 建议组件 | 职责 |
| --- | --- |
| HomePage | 页面布局、轮播数据适配、指针与导航交互转发，不持有业务偏好和第二份播放状态。 |
| HomeViewModel | 页面状态、栏目快照、刷新、重试、导入转发和主题播放命令。 |
| HomeRecommendationService | 生成偏好摘要、候选、排序、多样性和理由；输入为稳定的数据快照，输出曲目 ID，不依赖控件。 |
| 推荐查询边界 | 从 MusicDatabaseService 读取有时间窗口的历史摘要；复用曲库版本，避免每次导航重读整库和历史表。 |

构造函数只保存依赖，页面激活与退出显式管理订阅、取消和任务。UI 状态、命令通知与集合更新统一发布到 DispatcherQueue；后台计算不直接枚举会被 UI 修改的 List 或读取可变 Music 属性。按曲库版本制作并复用紧凑的不可变特征快照，结果在 UI 线程解析成现有 Music 引用。

使用 `SongsSourceChanged` 时要注意：当前 `NotifySongsSourceChanged` 在通知后才推进库版本，订阅者不能同步把收到的版本当作提交完成。应在 UI 调度边界合并刷新并重新读取版本，或者收敛为提交后通知。收藏、标签、艺术家分隔符和来源状态都要有明确的失效信号，不能仅依赖曲库总数变化。

按窗口历史生成偏好后扫描一次特征快照，以有界候选集合做重排，避免全库两两比较。每路候选上限 200，主排序、探索和流派代表合并后最多 600 项，每栏输出最多 12 项。卡片使用横向虚拟化列表，仅准备有限轮播图片，离页取消并明确资源所有权。

计算调度最多一个在途任务并合并新请求，以版本拒绝过期结果；不为每个扫描批次排队一次完整重算。大曲库快照制作需测量 UI 线程耗时，必要时分批并校验版本。没有页面消费者时只置脏，不维持后台刷新定时器。暂不承诺零分配、固定内存占用或具体毫秒收益。
