# 首页推荐与后台音乐分析

更新：2026-11-02。本轮已实现校准 DSP 默认路线、推荐展示去重、Last.fm 社区增强及设置页进度。

## 进程与职责

主程序负责曲库分页、任务队列、版本检查、持久化、曲库尺度校准、偏好向量、推荐分配和 UI 状态。`AudioAnalysisWorker.exe` 只负责本地音频解码与标准 MIR 特征提取。`AudioPlayer.exe` 继续负责播放；仅新增缓存根目录的可选 IPC 尾字段，响度缓存跟随统一位置，不改变输出模式或重建播放会话。

分析实现使用独立编写的通用 FIR、FFT、MFCC、频谱、起音自相关和动态统计。无第三方分析二进制、预训练权重或专有系数表。分析源码与发布 worker 不包含外部产品标识或逆向资料。研究材料不进入应用默认编译和分发。

## 输入、版本和调度

- 仅本地绝对路径及当前版本完整 WebDAV 缓存进入提取。UNC、映射网络盘、URL 和 `.part` 不作为分析输入；FFmpeg 只允许 `file` 协议。缓存未命中不建目录、不预留空间、不下载。
- WebDAV 使用完整文件共享只读租约，不阻断同时开始的离线播放；活动下载稍后扫描。清理、目录切换、来源删除或版本变化使迟到结果失效，进程退出前不提前归还在途租约；重复释放幂等，最后一个读者离开后才删除待清理文件。
- 本地指纹使用路径、大小、修改时间；WebDAV 使用来源、Href、ETag、服务器修改时间和长度，缓存 LRU 的本地 mtime 不构成音频版本。
- 在缓存库加载完成后显式启动。来源/曲库变化唤醒扫描；启用时每5分钟检查遗漏及本地版本变化，关闭时无周期扫描。失败按同一文件版本退避24小时。
- 单生产者、单消费者；任务预读一并读取版本状态及BLOB长度，避免为跳过已分析曲目再复制BLOB；提交前仅查询当前曲目。队列容量16，仅保存值快照，另有64行预读页。不开每曲一个并行任务，不提前持有排队项的文件租约。
- 默认10%单逻辑核 CPU 占空比，按实际进程 CPU 时间补休眠，优先级 BelowNormal。主程序使用有限超时；取消必须终止并等待实际 worker 退出。
- 批次完成主动释放 worker；独立协议客户端在空闲20秒或 stdin 关闭时也会退出。关闭分析、应用退出均停止生产者、观察在途任务并释放进程。无周期强制 GC 或工作集修剪。

## DSP 与校准

每首在20%、50%、80%附近各取10秒，解码到32 kHz单声道，再独立低通下采样到16 kHz。128维包含 MFCC、频谱形状/对比、移调不变音级间隔、logmel、起音自相关和动态统计。

worker 为每批复用 PCM、解码 scratch、FFT 与统计缓冲。FIR 内积、连续旋转因子的 FFT 蝶形、功率谱/开方以及归一化和余弦使用硬件 SIMD；保留标量分支。专用有深度上限的 introsort 避免按帧分配比较委托，退化时回退堆排序。

SQLite 按曲目版本保存三个原始片段（384个float，1536 B/曲目），便于曲库统计变化时重新校准。主程序以64行分页做均值/标准差、偏好中心、评分三遍流式处理；在SQLite锁内同步借用BLOB视图，不按曲目复制特征数组，span不跨await，不长期保留全库向量矩阵。分析提交与评分期间由互斥边界保持原始分析行稳定；少于16条有效分析行时沿用元数据/收听推荐。原始文件变化期间仍受首页快照版本与取消检查约束。

校准逐片段执行尺度变换与 L2，再取均值并 L2。常量维度清零，损坏或非有限向量跳过。收藏与有效收听形成偏好向量；没有偏好时不制造声学个性化。所有 UI 通知在 DispatcherQueue 发布。

## 推荐分配与社区增强

轮播最多5首、侧卡最多3首，各自使用独立集合；轮播、侧卡、主栏、常听、探索共享曲目 ID 和保守的完整艺术家＋曲名排除集合。每栏继续按艺术家、专辑和流派分散选择。曲库不足时减少独立展示项，不补回重复歌曲；仅有同曲版本时保留至少一个主栏播放入口，无独立精选时隐藏轮播。

元数据基础分保留原语义；可用的校准音频亲和及社区相似关系作为附加分，缺失时维持本地路线。推荐理由分别本地化。队列为发布时的固定曲目快照，不随后台分析或社区刷新改变正在播放的队列。

Last.fm 增强仅在已连接且启用时后台运行：最多8条收藏/播放偏好种子，分别调用 `artist.getSimilar`、`track.getSimilar`，每次最多40项，艺术家种子去重。复用现有账户版本、身份取消与共享网络请求槽，两请求间让出槽并间隔300毫秒。成功缓存6小时，失败退避30分钟；缓存限本次应用生命周期。首页只消费已发布快照，不等待网络。仅匹配当前可播放曲库的艺术家/曲名，不生成远程播放地址。断开、关闭或切换账户立即清除影响，拒绝旧账户迟到结果。

接口依据：[artist.getSimilar](https://www.last.fm/api/show/artist.getSimilar)、[track.getSimilar](https://www.last.fm/api/show/track.getSimilar)。本轮未用真实账户执行线上请求。

## 设置与兼容性

通用→高级中的「后台音乐分析」SettingsExpander 提供持久开关，显示已完成、已发现、排队、失败数量，以及当前曲目和运行阶段。发现数量随分页扫描增加，队列数表示有界队列中的项，不冒充全库剩余数量。通知合并后在 UI 线程发布，关闭设置消费时解除订阅。

新增开关缺省开启；已有安装首次升级也使用该缺省值，可随时关闭。关闭后停止后台扫描和音频评分，保留已保存特征供将来重新启用。本轮不引入 EfficientAT 运行时或模型。

## 验证与资源证据

环境：Core Ultra 7 255H、16逻辑处理器、Windows、.NET11 NativeAOT，暖文件缓存；不是低端设备实测。

- NativeAOT 数学回归覆盖真实音乐、静音、噪声、纯音及排序边界。排序优化的标量输出与原始标量逐位对齐，SIMD 最大特征差约1.57e-5；提取循环测得托管分配0 B。
- 同机短测：原始标量约53.60 ms/片段，优化排序后的标量48.58 ms，完整SIMD43.23 ms。两类优化分别有贡献，不能将全部改善归于SIMD。
- 实际发布 worker 连续180秒、120个真实曲目任务：单逻辑核 CPU约10.00%，峰值工作集27.65 MiB，峰值私有提交18.89 MiB，句柄范围166–169，正常退出码0。60–120秒对120–180秒私有提交中位增加约2.13 MiB，不能宣称完全不增长或无泄漏。
- 十万行真实SQLite、合成向量的NativeAOT容量探针：三遍校准及评分约1.78秒，累计托管分配14,716,048 B（约14.03 MiB），未包含夹具创建。纯元数据推荐重排的十万条探针约160毫秒、8.01 MiB；两项分别测量，不相加冒充进程峰值。
- 通过主项目Debug/x64构建、39项推荐回归、24项NativeAOT集成、8项社区增强、742项完整Last.fm回归、本机模拟WebDAV回归，以及实际WinUI设置进度/快速开关/退订与首页轮播侧卡去重绑定回归。
- 完整管线仍包含解码、JSON协议和数据库分配，不能称整体零分配。原生累计分配次数/字节未采集；短测不证明小时/天级生命周期正确。
- 推荐回归、真实解码/取消/缓存租约/版本/重启/空闲退出集成、Last.fm增强及完整历史队列回归、WinUI设置进度和首页绑定回归均在独立 `_tools` 工程验证。最终结果与复现命令见下方工程。

复现工程：`_tools/AudioAnalysisMathRegression`、`AudioAnalysisRegression`、`AudioAnalysisUiRegression`、`LastFmRecommendationRegression`、`LastFmRegression`、`HomeRecommendationRegression`、`HomeUiRegression --recommendation-slots`。真实音频不进入仓库；数学和解码回归在缺少本地研究PCM/清单时使用确定性音频夹具，也可显式指定音频文件。

原始日志和资源计数器位于 `_tools/artifacts/analysis-*`；发布 worker 位于 `Player/AudioAnalysisWorker.exe`。构建主项目时会按源码时间更新 worker。验证不覆盖低端实机、真实 Last.fm 账户或长期数小时全库扫描。

## 统一缓存目录与组件诊断（2026-11-02）

- 原始特征：`<关于页缓存位置>/Analysis/Features.db`，仍为每曲1536 B特征加版本信息；通过主库连接附加独立SQLite缓存，分页借用BLOB不变。偏好恢复后首次使用才打开目录，并用SQLite内部复制迁移原主库 `AnalysisRecord`。迁移成功才删除旧表，不执行VACUUM；分析开关留在主库。切换目录后按需建立新缓存，旧目录保留；跨目录的在途多遍评分丢弃结果。
- 响度：`<缓存位置>/Analysis/Loudness/*.bin`。原位置是 `%LOCALAPPDATA%/WinUIMusicPlayer/LoudnessCache`；新版本按需重新建立，不删除旧位置。缓存位置通过可选尾字段传到播放进程；长Unicode路径使用有界可变长载荷和池化发送缓冲，空尾字段保持旧载荷兼容。切换目录后不向旧目录发布迟到响度结果。
- 封面仍在根目录 `.bin`、`Cache`、`WebDav/Covers`，WebDAV音频仍在 `WebDav/Audio`。关于页大小统计包含 `Analysis`；现有清理封面/清理WebDAV按钮保持各自范围。
- `OneShotLyricsCache` 含用户编辑和恢复记录，作为持久歌词数据保留在应用本地目录，不当作可随意清除的派生缓存。PreparedCorrection、AtmosProbe及Last.fm推荐缓存仅在内存；主库、历史、账户和歌词数据库不迁移为缓存。
- 独立分析程序使用 `Assets/icon.ico`。构建输入包含图标，改图标会触发重新发布。

`UiLayoutDiagnostics` 在正常运行时只维护256条值快照；使用弱表/弱引用，不在全局持有页面。组件名称、父级路径、测量约束、尺寸变化与当前可视树在 `LayoutCycleException` 发生时捕获，在后台写入现有日志目录的 `Layout-yyyyMMdd-HHmmss-fff-PID.log`；常规日志记录文件位置。树最多512节点、深度24、文件最多256Ki字符，每30秒最多一份、每进程最多六份，磁盘保留20份。日志不采集控件文本、歌曲名或URL。退出阶段拒绝迟到记录并等待已捕获日志落盘。

启用 WinUI `LayoutCycleTracingLevel.High`：原生属性/Measure/Arrange循环详情输出到原生调试器并保留在stowed异常转储中，不声称这些原生行已自动转入文本日志。依据：[微软布局循环追踪文档](https://learn.microsoft.com/en-us/windows/windows-app-sdk/api/winrt/microsoft.ui.xaml.debugsettings.layoutcycletracinglevel)。文本日志给出最近参与布局的候选组件，不能单凭最后一条日志断定根因。

本轮验证：真实WinUI树上的注入异常确认组件名称、父路径、尺寸历史与可视树落盘；10000次预热后的单独记录调用测得0 B分配，这不代表初始化/异常捕获或整体诊断零分配。首页1806次连续缩放加660次窄窗口/0～3拼贴切换、设置240次缩放/展开/进度更新通过，包含开启组件诊断的首页测试。原用户报告未复现，不能声称已确定具体组件或彻底修复。缓存迁移/切换/失败恢复通过NativeAOT，原24项真实解码与资源生命周期集成通过；响度和DSP19项回归通过。主项目Debug/x64构建通过（既有警告仍在）。

实际发布版 AudioPlayer 在补齐应用部署时的 FFmpeg 依赖后，通过隔离命名管道验证长Unicode缓存路径、DSP握手、状态及有序退出；命名管道集成在沙箱外运行，测试不连接真实账户或打开音频输出。原先的“方法不支持”来自缺少FFmpeg依赖的测试目录，非新缓存协议失败。
