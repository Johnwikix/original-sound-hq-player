# 设备校正第一阶段

> 以下记录第一阶段实现。全局配置拆分、草稿保留和取消音频 `.bak` 的后续行为见 [第二阶段](audio-settings-stage2.md)。

## 配置边界

- `Settings.json`：继续保存全局 DSP、输出偏好及应用设置。本阶段不拆 `AudioSettings.json`。
- `AudioCorrections.json`：与 `Settings.json` 同目录，保存 schema version、提交 revision、设备模式开关和设备绑定。绑定只包含卷积曲线或 IR 参数，不再复制全部 DSP 设置。
- `ConvolutionCurves.json`：继续作为可复用曲线预设库，设备绑定保存快照，预设编辑不会隐式修改其他设备。

新文件和备份均不存在时，启动流程才从旧 `Settings.json.DeviceCorrections` 迁移。迁移成功后，后续常规设置保存省略旧字段。旧设置读取失败时不迁移；新文件损坏时尝试备份，未知 schema 不降级覆盖。文件恢复失败期间禁止设备配置写入。

## 保存和应用

设备配置经验证复制后，在后台写入同目录临时文件，刷盘后原子替换，并保留 `.bak`。成功才更新内存配置。随后发布共享邮箱并等待播放端确认；发送过程串行化，防止等待确认时邮箱被下一次写入覆盖。

弹窗分别显示保存失败和已保存但应用未确认。重试保留待提交快照；已保存的重试仅重新发送。已确认的同一快照跳过重复发送，播放端初始化时强制重发。

一般设置也改为原子替换，构建独立保存快照，读取失败时禁止覆盖。其 UI 提示仍沿用原有调用方式，不在本阶段全面改造所有设置入口。

## 试听和输出切换

试听协议携带发起时的稳定设备 ID、输出代数和单调命令顺序。播放端只接受当前输出匹配的命令，结束试听后拒绝较早命令。输出重建清空试听并改变代数，因此 A→B→A 也不能恢复旧 A 的草稿。

弹窗随实际输出和代数变化重新加载设备绑定；关闭设备模式恢复打开弹窗时的全局曲线。普通状态通知不会覆盖编辑中的草稿。

## 性能

- 共享邮箱只在锁内复制字节，反序列化移到锁外，播放端保留输入验证。
- FIR 系数和每个渲染器的历史、FFT 工作区分离。最多缓存四套曲线的准备结果，键包含曲线内容、采样率和声道数。
- WAV 文件不进入跨会话缓存，避免文件内容被覆盖后长期使用旧 IR。
- 相同曲线的输出重建保留准备结果并清空历史；不同曲线先移除旧滤波器，避免尾音进入新设备。
- 旁路时不为未使用的曲线启动准备工作；设备模式下新会话等实际输出解析后再准备卷积。
