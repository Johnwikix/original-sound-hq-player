# 协议内容与启动流程

## 内容来源

- `Legal/legal.zh-CN.json`、`Legal/legal.en.json` 是应用与官网共用的版本化正文。
- 弹窗的按钮、提示和错误文案覆盖现有六种界面语言；正文提供中文、英文，并在弹窗中明确说明、允许切换。
- 用户协议、隐私政策、免责声明相互独立。官网路径为 `/terms`、`/privacy`、`/disclaimer`。
- 旧的 GitHub `policy.md` 地址保留，内容由同一份隐私政策生成。
- 官网不由这些脚本自动发布；商店后台的协议和隐私政策链接需在发布时同步检查。

更新正文后同步并验证：

```powershell
python _tools/LegalContent/sync.py --website G:/SoftwareProject/vue/OriginalSoundPlayer/original-sound-player-page
python _tools/LegalContent/sync.py --website G:/SoftwareProject/vue/OriginalSoundPlayer/original-sound-player-page --check
```

只有实质性条款变更才更新 `AgreementAcceptanceStore.CurrentVersion` 与两份 JSON 的 `version`，普通软件版本更新不改协议版本。同步脚本检查三者一致。修改正文不能追溯剥夺既有购买或开源许可权益。

## 确认记录

记录位于应用可访问的 LocalApplicationData 下 `OriginalSoundPlayer/agreement.json`，包含协议版本、正文语言、UTC 同意时间。读取不写入；仅明确点击同意后保存。先写同目录临时文件再替换，失败时弹窗不关闭并允许重试。缺失、损坏或版本不匹配均重新提示。

MSIX 桌面应用存在文件系统重定向。本机开发包已实测的路径为：

```text
C:\Users\90684\AppData\Local\Packages\SennpaiStudio.528762A6196EF_z79ft30j24epr\LocalCache\Local\OriginalSoundPlayer\agreement.json
```

复位测试：完全退出播放器（启用了后台运行时需从托盘退出），删除或重命名上述文件，再重新启动。不要删除整个应用数据目录或数据库。不同签名/包标识应使用对应的 PackageFamilyName；非打包运行则通常位于 `%LOCALAPPDATA%\OriginalSoundPlayer\agreement.json`。普通应用版本升级不触发重弹，只有协议版本变化或记录无效才触发。

协议全文随应用打包，无需网络加载。已经同意当前版本时只读取小型记录，不加载正文。拒绝、Esc 或启动期间关闭窗口会清理已创建的托盘并退出，不保存尚未恢复的播放状态，不继续启动后台服务。

## 启动顺序与调整

1. 初始化数据库、加载设置及窗口位置，创建窗口与托盘并等待 XamlRoot 就绪。托盘的显示窗口和退出操作立即可用。
2. 启动最前拉起音频子进程并开始 IPC 连接（先于协议，连接进度由标题栏任务指示器显示）；随后检查协议记录，必要时等待独立协议弹窗。协议等待期间不启动文件夹监视、USB 扫描或 Store 查询，托盘的播放、设置、音量、播放模式和桌面歌词操作不可用；系统媒体控制尚未创建。
3. 同意后并行等待 Store 许可查询与缓存库加载；主界面立即显示，不等待播放引擎。IPC 连接、许可与缓存库（含播放状态恢复）在引擎轨汇合后推送首曲，推送完成前播放入口置灰。
4. 缓存旧文件清理在后台线程完成，并在恢复封面前汇合。仍保证许可结果就绪后才向播放端发送首批完整设置。
5. 恢复播放栏与音频设置；更新日志在交互启用后后台弹出，关闭时才记录已读版本。
6. 主界面已在 `StartAsync` 内窗口内容加载后立即注入（无 Loading 过渡层，首装协议弹窗覆盖其上）；`Host.StartAsync` 返回后仅将 `AppLifecycle` 转为 Ready，启用托盘命令、任务栏按钮、USB 监视、媒体控制、桌面歌词与快捷键；这一阶段不含 `await`。`IsInitialized` 仅兼容读取同一状态，不可单独赋值。

旧流程在窗口显示前等待 IPC，缓存目录枚举发生在 UI 线程，USB 和文件夹监视还会因构造 ViewModel 提前启动。本次调整这些依赖顺序，并以日志分别记录窗口就绪时间及协议确认后核心启动耗时；不将用户阅读时间计入后者。没有通过跳过扫描来牺牲音乐库一致性，也没有未经测量宣称具体提速比例。

启动失败或启动中退出仅清理本次启动的音频进程，避免遗留子进程；不走会保存空播放状态、等待尚在启动中的 Host 的常规退出路径。

## 首轮启动链路复查（2026-09-16，后续解耦见下文）

- **托盘回归已复现并修复**：`x:Load=False` 配合根 Grid 的 `FindName` 在实际打包版本返回 `null`，下一轮 UI 调度后控件仍不存在。改为启动结束后显式创建并挂到 `TrayHost`，先更新绑定，再 `ForceCreate(false)`，检查 `IsCreated`。不再依赖名称作用域或 Loaded 时机，也不误开后台效率模式。
- **就绪状态提前**：原流程在 HostedService 的 `StartAsync` 内设置就绪。交互启用现移到整个 Host 启动完成后，避免启动未完成却进入常规退出。
- **窗口关闭竞争**：`AppWindow.Closing` 始终先取消系统立即关闭，统一退出流程完成异步保存、停止服务及托盘清理后再退出进程。
- **IPC 失败返回成功**：重试耗尽时保留立即退出，同时抛出异常，阻止调用方把失败当作连接成功；不会为等待并行音乐库扫描而延迟退出。
- **前台状态**：启动期间仍记录真实 Activated 状态，但不提前解析桌面歌词 ViewModel；启用交互时采用该状态，避免用户切走窗口后仍被写成前台。
- **依赖顺序核查**：设置/窗口位置先于窗口；协议先于 Store 查询和文件夹监视（音频进程自 2026-09-18 起先于协议拉起，见下文）；许可/IPC/音乐库汇合后才推送完整音频设置；USB、快捷键和系统媒体控制在交互阶段开启。初始扫描与文件夹监视扫描共用 `LibraryOperationGate`，未改为互相争用音乐库的并发扫描。

## 验证

`_tools/AgreementRegression` 链接实际保存逻辑、ViewModel 与 JSON 源生成代码，覆盖首次启动、离线正文、语言/文档切换、明确同意、重复启动、版本变化、损坏记录、保存失败及重试。

本次实际打包运行验证了托盘注册（`Shell_NotifyIconGetRect`）、托盘设置命令、隐藏窗口后的托盘恢复、正常关闭与音频子进程清理，以及协议拒绝/关闭两条退出路径。协议显示期间核对没有音频子进程、没有托盘且未写同意记录。原有同意记录仅在测试期间临时备份，已按哈希核对原样恢复。协议回归和 Release 模式许可回归通过。

可重复的真实托盘断言见 `_tools/StartupSmoke/Assert-Tray.ps1`。普通 `dotnet build` 不保证刷新已注册开发包的 `AppX` 目录，实机测试前需部署本次构建并核对实际加载 DLL，避免验证旧版本。

尚未做实机故障注入的分支：IPC 连续连接失败、Store 长时间无响应、Explorer 重启、USB 热插拔及更新日志版本变更。本轮鼠标注入后期被系统拒绝，托盘退出菜单未完成独立自动化验收；常规退出已验证。不要把上述静态检查或共享退出实现等同于这些场景已经实测。

发布前人工验证：在未确认协议时检查音频子进程已随启动拉起且 IPC 重试静默进行；测试同意、拒绝、Esc、关闭窗口及托盘行为，拒绝路径应清理音频子进程且不写同意记录；确认更新日志不会与设置弹窗重叠；使用常用音乐库比较两项启动计时。已有商店用户的订单、退款及许可条款也应与商店页面保持一致。

## 本轮解耦后的行为

托盘创建已提前到协议之前；首轮记录中“启动结束后创建托盘”的方案已被替换。新的职责边界、清理顺序与验证结果见 [ApplicationLifecycle.md](ApplicationLifecycle.md)。

本轮实机验证了协议期间托盘已注册且当时无音频子进程、协议拒绝/关闭退出、更新日志关闭后才启用主界面，以及正常退出清理音频进程。验证已确认分支使用标明 test-only 的临时夹具；已删除，恢复测试开始时协议记录不存在的状态。

2026-09-18 起音频子进程与 IPC 连接移到用户协议之前启动（与数据库初始化、协议阅读并行），上文"协议先于音频进程""协议期间无音频子进程"的旧约束作废；拒绝协议由 ShutdownCoordinator 清理音频进程与 IPC，IPC 重试循环检测退出后静默结束。改序后的实机复验尚未执行。
