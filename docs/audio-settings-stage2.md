# 全局音频配置第二阶段

## 编辑草稿修复

未启用设备校正时，输出插拔、默认输出回退、相同端点重建只更换试听目标，不重载曲线。未保存的节点、预设命名输入及增益保留，并在新输出可用后恢复试听。进入设备模式前暂存全局草稿，退出时恢复这份草稿；关闭弹窗仍取消试听，不提交配置。

## 配置职责

| 文件 | 内容 |
| --- | --- |
| `Settings.json` | 应用外观、歌词、窗口、快捷键等一般偏好 |
| `AudioSettings.json` | 全局 DSP、输出模式、设备 ID / 名称、延迟、淡入淡出、DSD / DoP 和实验输出选项 |
| `AudioCorrections.json` | 按设备应用开关和设备校正快照 |
| `ConvolutionCurves.json` | 可复用曲线预设 |

均衡器和播放状态沿用原有独立存储。本阶段不改播放端音频协议。

## 迁移与可靠性

`AudioSettingsStore` 保存带 schema version、revision 的不可变快照。首次不存在新文件时，从旧 `SaveSettings` 的 13 个音频字段导入。新文件写入成功后，启动流程再清理 `Settings.json` 中对应字段；如果清理失败，下次启动以新文件为准并重试清理，不重复覆盖音频偏好。

旧字段保留为只用于迁移的可空属性，常规写出时省略。UI 读取和保存音频的映射位于 `MusicDatabaseService.AudioSettings.cs`，文件读写与音频模型独立于 WinUI。

音频保存先取得 UI 快照，再按调用顺序串行派发到后台；不在线程池中读取 ViewModel。无变化的音频快照不序列化、不写盘；一般设置也比较已提交内容，音频单独变化不会反复重写一般设置文件。两份文件分别原子提交，不假定它们具有跨文件事务。

确定损坏的设置文件隔离后原子重建默认值，不重新导入旧音频字段。默认值成功提交后恢复正常保存。未知版本、读取失败或重建失败时不覆盖源文件，也不推进仓库的已提交快照；排除故障后可重新加载。

## 所有设置均不生成 `.bak`

`Settings.json`、`AudioSettings.json` 和 `AudioCorrections.json` 统一通过 `AtomicSettingsFile` 使用同目录临时文件、刷盘和无备份原子替换。接口不再提供生成备份的选项。其他窗口状态、播放状态和版本记录原本不生成常规备份，其损坏隔离文件也不再使用 `.bak` 后缀。

不读取旧 `.bak` 恢复设置，也不批量删除磁盘上已有的备份。文件缺失时使用首次迁移/默认初始化流程；文件内容损坏时保存一份 `.corrupt-唯一编号` 诊断文件，再原子提交默认值。重建失败保留原主文件，避免下次启动误判为首次迁移。没有有效历史副本时接受原设置丢失，以恢复可用性为目标。

共享/锁冲突延迟 100ms 重试一次；持续 IO 错误和权限错误不按损坏处理。音频 schema 版本检查先于本版本必填字段验证，未来版本即使不含当前字段也不会被重置。恢复行为写入日志。

## 评审后的健壮性修复

- 启动校正同步未确认时记录日志并继续主页初始化。初始化后最多延迟重试两次，每次在串行发布入口读取最新绑定，退出时取消等待。失败清除旧的已确认快照，不能依赖旧记录跳过重发。
- IPC 服务保存同步失败状态；即使失败发生在设置页打开前，设备绑定区域也能显示错误并重试。校正错误与 IR 导入错误分开，保存、同步和枚举失败均记录异常。
- 曲线准备缓存按 LRU 淘汰，命中时复用链表节点；仍不缓存文件 IR，也未引入并发准备任务共享。
- 草稿读取只编码一次节点；临时文件清理失败不掩盖原始写入异常。

本轮将无备份策略扩展到一般设置，并为一般设置、全局音频及设备校正补齐默认值恢复流程。只有确认损坏才重置；未知版本和暂时无法读取的文件仍受保护。

验证：播放回归 264/264 通过（含新增 LRU 热点保留测试）；曲线预设与设置持久化回归通过；六语言独立资源键检查通过。启动失败降级及状态通知完成代码检查与 WinUI 构建，尚未进行真实 IPC 故障注入和 UI 人工验证。

- `SettingsPersistenceRegression`：真实设置模型及源生成 JSON 参与测试，覆盖全部音频字段迁移、无关 UI 字段保留、旧字段省略、幂等启动、无变化跳过 IO、写失败重试、并发完整快照、损坏重建后保存与重启、旧备份忽略、重建失败保护、瞬时/持续锁冲突和未知版本保护。

- WinUI 构建、NativeAOT 发布及随应用分发的 `AudioPlayer.exe` 同步更新。
