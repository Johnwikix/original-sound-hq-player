# 全局音频配置第二阶段

## 编辑草稿修复

未启用设备校正时，输出插拔、默认输出回退、相同端点重建只更换试听目标，不重载曲线。未保存的节点、预设命名输入及增益保留，并在新输出可用后恢复试听。进入设备模式前暂存全局草稿，退出时恢复这份草稿；关闭弹窗仍取消试听，不提交配置。

## 配置职责

| 文件 | 内容 |
| --- | --- |
| `Settings.json` | 应用外观、歌词、窗口、快捷键等一般偏好 |
| `AudioSettings.json` | 全局 DSP、输出模式、设备 ID / 名称、延迟、淡入淡出、DSD / DoP 和实验输出选项 |
| `AudioCorrections.json` | 按设备应用开关和设备校正快照 |
| `ConvolutionCurves.json` | 可复用曲线预设 |

均衡器和播放状态沿用原有独立存储。本阶段不改播放端音频协议。

## 迁移与可靠性

`AudioSettingsStore` 保存带 schema version、revision 的不可变快照。首次不存在新文件时，从旧 `SaveSettings` 的 13 个音频字段导入。新文件写入成功后，启动流程再清理 `Settings.json` 中对应字段；如果清理失败，下次启动以新文件为准并重试清理，不重复覆盖音频偏好。

旧字段保留为只用于迁移的可空属性，常规写出时省略。UI 读取和保存音频的映射位于 `MusicDatabaseService.AudioSettings.cs`，文件读写与音频模型独立于 WinUI。

音频保存先取得 UI 快照，再按调用顺序串行派发到后台；不在线程池中读取 ViewModel。无变化的音频快照不序列化、不写盘；一般设置也比较已提交内容，音频单独变化不会反复重写一般设置文件。两份文件分别原子提交，不假定它们具有跨文件事务。

损坏或未知版本的音频文件保留原样并阻止该仓库继续写入，不重新用旧字段或默认值覆盖。写入失败不会推进仓库的已提交快照，后续保存可重试。

## 不再生成音频备份

`AudioSettings.json` 和 `AudioCorrections.json` 使用同目录临时文件、刷盘和原子替换，不生成 `.bak`。取消常规备份意味着无法从本版本自动生成的上一份文件恢复人工损坏。

上一阶段遗留的 `AudioCorrections.json.bak`：主文件有效时清理；如果需要从旧备份恢复，先成功恢复主文件，再清理备份。被占用的旧备份留待下次清理。整个流程在应用下次启动时执行；不会批量删除其他配置备份。

## 验证

- `CurvePresetRegression`：全局未保存草稿经过断开、默认输出回退、A→B→A、同端点重建、模式往返后保持不变，试听重新指向实际输出。
- `SettingsPersistenceRegression`：真实设置模型及源生成 JSON 参与测试，覆盖全部音频字段迁移、无关 UI 字段保留、旧字段省略、幂等启动、无变化跳过 IO、写失败重试、并发完整快照及损坏 / 未知版本保护。
- `PlaybackSwitchRegression`：完整 263 项回归，包括旧校正备份的一次性恢复和清理。
- WinUI 构建、NativeAOT 发布及随应用分发的 `AudioPlayer.exe` 同步更新。

本次新增的插拔修复通过模拟输出通知验证，未代替真实硬件验证。
