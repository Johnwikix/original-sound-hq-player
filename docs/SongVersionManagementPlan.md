# 歌曲版本管理完整方案

日期：2026-11-11。状态：用户已授权并完成首版实现；本文保留完整设计，首版记录见第 16 节，当前自动关联交付与验证见第 17 节。未打开或迁移用户实际数据库。本版统一取代前文逐字段选择共享标签的建议。

## 1. 目标与范围

管理同一歌曲的重复音频文件，支持不同格式、编码、目录和本地／WebDAV 来源。`Song` 表示分组及共享用户状态，现有 `Music.Id` 继续表示具体文件版本。歌曲标题、艺术家、专辑信息完整且规范化一致时自动关联；归组后，各版本的标签、封面、音频信息都保留，并按当前所选版本展示。

当前交付：旧库启动自动关联、扫描／导入／远程标签补全后的增量关联、手动合并预览、版本详情与切换、默认自动选版／手动固定、精确播放、共享收藏／歌单／歌词、拆分例外和可恢复记录。不需要音频指纹、在线识曲或外部录音 ID。

Remaster、Live、Remix、重录等明确内容版本独立管理。跨专辑相同音频仍是用户指出的待讨论问题；本方案采用“首版保持分开”的建议默认，不将其标记为已经确认的决定。不做重复文件清理、自动转码、批量标签同步、多端同步或完整作品／发行数据库。

## 3. 分组判定

### 3.1 候选键与稳定身份

候选比较键为 `(NormalizedTitle, NormalizedArtist, NormalizedAlbum)`。只规范化 Unicode 表示、大小写和首尾／连续空白，保留原值及 Remaster、Live、年份、Edition 等限定词；不任意删除括号，不识别模糊别名。

三项齐全且一致时自动归组；首次迁移与新扫描先建立独立 Song 身份，再在对 UI 发布前批量关联。手动拆分／撤销例外保持独立。空值、UnknownAlbum／UnknownArtist 等占位符不参与自动匹配。艺术家首版按现有完整字段规范化比较，不能只比较主艺术家而丢掉合作艺术家。

SongId 为独立本地 ID，比较键不是主键、不是唯一约束。单版本歌曲三项标签修改后，重新索引并自动关联同键歌曲；多版本歌曲编辑单个文件不隐式拆组。合并保留最早 SongId，原组作为可恢复记录保留；文件 Music.Id 不变。

### 3.2 边界表

| 场景 | 首版行为 |
| --- | --- |
| 三项一致，FLAC／MP3／AAC 等不同格式 | 自动关联，文件原样保留 |
| 三项一致，同格式但目录／来源不同 | 同样支持归组 |
| 单曲、原专辑、精选集的音频实际相同 | 建议分别管理各专辑中的 Song |
| Original／Remaster 或不同 Remaster | 已知差异时独立管理，不能被三项相同覆盖 |
| Live、Remix、重录、伴奏、剪辑版等 | 明确内容不同则保持独立 |
| 流派、作曲、作词、封面等不同 | 不要求统一，按所选版本显示 |
| 年份、专辑艺术家、目录编号、指挥、曲序／碟序冲突 | 预览提示核对是否不同发行／内容，缺失字段不当作冲突 |
| 时长差异 | 小幅编码延迟可接受；明显差异提示复核，不单靠时长判身份 |
| 所有标签相同但实际有未标注内容差异 | 首版无法从标签证明相同，允许拒绝归组并保存拒绝关系 |
| 同专辑内有意重复收录到不同曲序 | 三项相同时仍自动关联；歌单重复位置保留，可手动拆出不同录音 |

时长异常提示可初用 `abs(d1-d2) > min(5秒, max(2秒, 1% * min(d1,d2)))`，须以样本校准，不能宣传为判定阈值。未知时长不提供相同证据。

同一路径重复发现与 Song 归组分开处理：本地使用规范化路径；远程使用 `(SourceId, Href COLLATE BINARY)`，不能把远程 Href 全部转小写。候选按三项键分桶／索引检索，不做全库两两比较，不做相似关系传递合并。

## 4. 数据模型与字段归属

### 4.1 Song 保留什么

| 数据 | 所有者／用途 |
| --- | --- |
| SongId | 稳定分组身份 |
| GroupTitle、GroupArtist、GroupAlbum | 分组标识及稳定的歌曲／专辑分类；初建取原 Music 三项，不是额外 info 的共享副本 |
| PreferredMusicId? | null 表示自动选版；非空表示用户手动固定，必须属于本 Song |
| IsFavorite、FavoriteOrder | 共享收藏及其排序 |
| Revision、状态 | 归属、首选、共享修改的条件提交及墓碑状态 |
| 默认歌词及修订 | 通过 SongLyrics 存储 |

Song 不新增 Genre／Composer／Year 等共享标签，也不保存一套逐字段补齐的 info。首版封面也跟随具体版本，不另做共享封面选择。

### 4.2 Music／Version 保留什么

继续使用原 Music.Id，增加 SongId、MetadataRevision 和必要的资源验证／状态。默认策略需要的 CodecId、EncodingKind（已知无损／有损／未知）及读取状态也按版本保存，由元数据读取／媒体探测边界提供；旧库先标未知，不为迁移强制解码全库。容器 Extension 保持原义，不能直接充当 CodecId。所有现有文件信息留在该版本：标题／艺术家／专辑原值、专辑艺术家、流派、作曲、作词、指挥、目录编号、年份、曲序／碟序、ImageHash／版本封面、路径、来源、格式、码率、采样率、位深、声道、时长、文件时间等。

技术信息和附加标签的未知／未读取／已读取但缺失状态分开。各版本数据不互相补齐：选中 MP3 缺作曲就显示未填写，不从 FLAC 借一个值，让用户误以为 MP3 有该标签。

原数据库保存的版本标签、用户编辑结果和文件原值差异仍沿用现有数据库／显式文件写入边界；本次归组不会把数据库标签自动写回文件。首版远程文件标签编辑沿用现有只读约束，不新增远程写入能力。

### 4.3 其他对象

| 对象 | 内容／约束 |
| --- | --- |
| PlaylistEntry | 沿用 PlayListMusic.Id；SongId、Order、RequestedMusicId?、LegacyOriginMusicId?；同 Song 可多次出现 |
| QueueEntry | 沿用 EntryId；SongId、RequestedMusicId?、来源范围、已解析实际 MusicId；遍历顺序不因归组重建 |
| SongLyrics | 完整 LyricsDocument、Revision、来源、时间基准版本 |
| VersionLyrics | MusicId、偏移、修订、对齐状态、可选覆盖文档；默认继承 SongLyrics |
| LyricsArchive | 原整组文档、来源、修订、原偏移／时间基准、操作 ID、归档原因 |
| PlaybackHistory | 保留 MusicId、标题／艺术家／专辑／时长快照；增加 SongIdAtPlay 和必要资源修订 |
| SongOperation | 合并／拆分的前后身份、修订、共享状态、歌单／歌词快照、提交／恢复状态 |
| SongAlias／历史映射 | 已合并 Song 指向目标；旧引用可解析，拆分不盲目复活别名并重定向后来的所有新引用 |

持久化约束：每个有效 Music 恰一 Song；首选／固定版本必须属于目标 Song；历史墓碑不能因活跃版本删除丢失。索引覆盖 Music.SongId、候选键、歌单 `(PlayListId, Order, Id)` 和别名。核对 sqlite-net 连接的外键配置，归属还必须在服务事务内检查。

旧 Music.IsFavorite／LyricsOffsetMs 等需要兼容时仅提供明确的共享／版本状态投影，不能保留两套可独立修改的权威状态。原 Music.PlayCount 保留为版本累计值，歌曲汇总求和；不从不完整历史重算。

## 5. 当前查看、首选、实际播放与列表展示

| 状态 | 生命周期 | 作用 |
| --- | --- | --- |
| SelectedVersionId | 每个详情会话独立，默认不持久化 | 决定当前详情的标签、封面、文件信息、频谱和编辑目标 |
| PreferredMusicId? | Song 持久化 | null 自动；非空为用户手动固定的普通播放首选 |
| ActualPlayingMusicId | 当前媒体会话 | 决定播放器、SMTC、桌面／任务栏展示、进度、历史与分析实际目标 |
| DisplayVersionId | 列表按规则派生，不另存偏好 | 没有查看选择时提供一套完整的版本 info |

Selected 的变化只切换查看，不能自动播放、改首选或覆盖 ActualPlaying。设置首选也不重启当前解码器。多个详情窗口可分别查看同一个 Song 的不同版本；共享收藏和歌词相同，查看选择与标签草稿各自独立。

### 5.1 详情打开规则

1. 从文件夹、版本行、精确队列条目打开，使用入口携带的 MusicId。
2. 从当前播放条目打开，使用该 Entry 实际播放的版本；不能只凭同 Song 就选到别的重复队列项。
3. 从普通 Song 行打开，使用该行 DisplayVersionId，即使它离线也能查看数据库中已有 info。
4. 同 Song 再次打开不同版本，复用已有会话并切换选择，保留各版本及共享歌词草稿；不依赖 Music 引用相等决定整页重建。

### 5.2 info 来源

详情中的标题／艺术家／专辑原值、额外标签、封面和技术信息都取 SelectedVersion；分组标题作为独立小标签／导航上下文。未保存标签可按现有编辑器显示该版本草稿，但只在本会话预览，列表与播放器仍显示已提交资料。

歌曲列表、收藏、歌单和推荐没有 SelectedVersion：手动首选存在就用其持久版本资料；自动模式用第 6 节的稳定代表版本。限定来源的视图只在范围内选代表。离线状态或一次播放回退不改变列表展示版本，不因网络抖动重排流派／年份等列。

列表／专辑分组身份使用 GroupTitle／GroupArtist／GroupAlbum；其他显示列及对应排序从同一个 DisplayVersion 快照取得。搜索同时匹配分组标识和任一版本原始标签／文件名，标明命中版本；不把多个版本的 Genre 等拼成一套 info。改变手动首选后，代表版本信息及相应排序可刷新，需批量发布。

播放器、SMTC、Last.fm 和桌面／任务栏歌词使用 ActualPlayingVersion 的元数据及媒体时长；详情切换查看另一版本不会改变它们。详情显示“正在查看 MP3”“正在播放 FLAC”等简短标记；自动回退时让用户知道实际使用的版本。

封面属于版本：详情跟 Selected，列表跟 Display，播放跟 Actual。当前版本缺封面用现有默认图，不静默借其他版本封面。频谱也跟 Selected；只有 Selected 与 Actual 的媒体身份／资源修订一致时显示播放游标并允许直接 seek，不能用另一版本的毫秒时间跳转当前媒体。

## 6. 默认首选版本策略

### 6.1 自动与手动

默认 PreferredMusicId 为 null，即自动选择。单版本 Song 自然使用唯一版本。用户点“设为首选”后固定 MusicId；“恢复自动选择”清空它，不需要再保存一份自动首选 ID。

迁移保留旧存档中的精确版本意图，但不虚构旧用户曾手动指定首选。合并时保留目标 Song 已有的手动首选；多方手动首选冲突在预览中确认。全部处于自动模式时继续自动，不把被点击的某文件误记成永久手动偏好。

### 6.2 自动策略的排序

先限定入口来源／离线模式和当前解码器／输出能力，再按如下顺序选择候选：

1. 可靠元数据确认的无损／未压缩音频优先，其次已知有损，编码类别未知的排后。不能只凭容器后缀猜无损，DSD 与 PCM 不做“谁天然更好”的额外排序。
2. 同类别优先可用本地文件，其次匹配资源版本的完整缓存，再其次可连接的远程文件。由此，可播放的远程无损可优先于本地有损；开启仅离线时远程未缓存候选已被范围排除。
3. 同编码、同采样规格／声道的有损副本可优先已知更高码率；不同编码之间不直接比较 kbps。无损文件不按压缩后码率判音质，不把更高采样率／位深直接视为更好。
4. 剩余使用稳定入库身份排序，不受目录枚举顺序影响；不擅自升级声道、不同混音或已知 Remaster。

实现必须构造稳定且可传递的顺序：先按编码类别和来源层分桶，再将有损候选按编码／采样规格分组，组内比较有效码率，组间按最小 MusicId 的稳定顺序；未知值排在组内已知值之后。不要写“同编码比码率，否则比 ID”的非传递比较器。

上述是产品默认偏好，不宣称采样参数能证明实际听感。首版不增加多个全局排序预设；用户要另一个版本时可直接手动指定。

### 6.3 稳定展示与真实可播放性

DisplayVersion 在手动模式使用固定版本（包括离线但仍保留资料的版本）；自动模式按目录中已知的编码类别、静态本地／远程属性和稳定排序选代表，不主动探网、不随连接或缓存 LRU 改变。展示代表与本次实际可用版本允许不同。

实际播放按当前可用状态／缓存验证结果执行自动顺序；手动模式先尝试所指定版本，普通播放不可用时再按自动策略尝试其余成员，保留原手动首选。可用性检查与缓存租约在后台进行，最后已知状态仅作提示，不能代替开始播放时的校验。编码类别未知时只按现有资料排序或按需补读，不为一次请求先读取整个组的远程文件；补读结果不得夺回已经确认开始的版本。

新版本加入、已有元数据／支持能力变化、切换自动／手动，只影响下一次选版及相应展示刷新。当前音频保持不变。临时回退成功不把该版本写成新首选。

### 6.4 策略示例

| 候选 | 自动模式结果 |
| --- | --- |
| 本地可用 FLAC 与本地 MP3 | FLAC |
| 可连接远程 FLAC 与本地 MP3 | FLAC；若失败则 MP3 |
| 本地 FLAC 与远程同类别无损 | 同级优先本地 |
| 同规格本地 MP3 320 与 MP3 128 | 320 |
| AAC 256 与 MP3 320 | 不凭 kbps 跨编码比较；用来源和稳定组次序 |
| 首选输出不支持、另一个版本支持 | 普通歌曲播放选可支持版本；不永久标记原文件损坏 |
| 用户手动固定 MP3，FLAC 同时可用 | MP3 |
| 手动 MP3 不可用，FLAC 可用 | 普通歌曲播放可回退 FLAC；明确播放 MP3 则失败 |

## 7. 播放意图、队列与失败处理

普通歌曲列表、收藏、歌单默认条目、推荐、专辑歌曲使用“播放歌曲”；从当前详情、版本行、文件夹文件行和打开文件使用“播放此版本”。详情主播放按钮明确命名“播放此版本”，目标为 SelectedVersion，避免看着 MP3 信息却播放首选 FLAC。

明确版本请求失败不跨版本替换。普通歌曲请求在尚未确认开始播放时可尝试其他成员，每个版本最多一次，受现有来源退避／超时、请求总预算和取消代次约束；全部失败则手动请求显示失败，自动导航最多遍历一遍队列，不能循环尝试同源。

已经出声后断流，首版仅按同一版本恢复／失败，不跨版本续播。更改首选、切换查看、合并／拆分不重开当前解码器、不清进度、不额外记播放会话；明确点另一版本从头开始播放。

QueueEntry 保存 SongId、可选 RequestedMusicId、来源范围、EntryId 和实际解析版本。重复 Song 也有不同 EntryId，按出现项定位。详情对已有条目“播放此版本”只将该出现项改为精确意图；其他出现项和 Song 默认首选不变。按来源页建立新队列时，保留其余条目的原意图。

来源过滤／仅离线限制随条目保存，不能只是过滤 UI 后后台跨源选版。队列存档加 SchemaVersion，保留 EntryId、随机顺序及当前实际 MusicId；旧 MusicId 存档通过映射恢复为原文件精确意图，不在升级恢复时换文件。

候选、预取和引擎确认都带选择代次、EntryId、Song／成员／资源修订。首选或成员变化使未开始的 Gapless 计划失效，已确认交接不回滚。旧网络／引擎回调不能夺回新选择，Play／Pause 等显式意图不能被单飞去重丢弃。

## 8. 详情 UI、草稿及保存边界

复用 MusicDetailControl、MusicDetailsPanel 和 MusicDetailsWindow，不另做一套版本详情。增加版本 Pivot 或紧凑版本选择器，版本行展示格式、码率／采样率／位深／声道／时长、来源、路径、状态、自动模式／手动首选、当前播放标记。

提供动作：查看此版本、播放此版本、设为首选／恢复自动、关联已有文件、拆出、移除版本、定位文件。收藏和加入歌单针对 Song；文件／标签／封面／频谱／偏移针对 Selected。仅本地开放现有文件写入能力。

### 8.1 草稿所有权

一个详情会话持有：一份共享默认歌词草稿、按 MusicId 键控的标签／封面／偏移／覆盖歌词草稿、独立 SelectedVersionId。切换版本只切换子会话，不重建整页；未保存版本显示提示标记，切回能继续编辑。

只有当前或曾编辑过的版本需要物化编辑器／草稿；不因打开 N 版本组就并发读取 N 个文件、加载 N 张封面、启动 N 个频谱分析。切走时取消可取消读取，暂停非当前频谱工作；未结束任务继续有明确收尾责任，不能用取消等待代替真正停止。

每个标签补读、封面解码、频谱请求带 MusicId、资源修订和查看代次。迟到结果最多更新仍匹配的版本子会话，不能覆盖当前另一个版本或它的新输入。保存捕获不可变目标快照；用户随后切换 Selected 不改变这次保存的文件目标。

### 8.2 保存命令

| 命令 | 影响 |
| --- | --- |
| 保存当前更改 | 当前版本有改动的数据库标签／封面／偏移，加上本次明确改动的共享歌词或版本歌词覆盖；其余版本草稿不提交 |
| 写入此文件 | 明确选定当前本地 MusicId，预览要写入的标签／封面／歌词快照；只写该文件，允许占用时排队 |
| 关闭详情 | 有任一未保存草稿时按统一交互保留／放弃；不因切换版本隐式清空 |

拆分 SaveVersionMetadata 与 SaveSongLyrics／SaveVersionLyrics 用例；若一次按钮保存多项，预先捕获 dirty 字段和各修订，在同一数据库事务检查后提交。只改标签不能要求／增加共享歌词 Revision，否则不同版本的独立编辑会相互制造无关冲突。

版本标签修改不自动重写共享歌词，写文件也不默认烘焙当前共享歌词／偏移，必须明确选择输出内容。远程共享歌词／收藏操作不受远程文件只读限制。

保存成功只清除已提交且草稿代次仍匹配的 dirty 状态；保存期间的新输入和其他版本草稿保持。详情保存后保持打开，不沿用当前保存就关闭的逻辑。应用退出通过 EditorSessions 取消读取、等待已接受写入并逐项清理，单项失败不跳过其余资源。

### 8.3 修改分组三项时

单版本 Song 编辑标题／艺术家／专辑，可在同事务同步其 Group 三项，保持旧单曲体验。多版本组修改一个版本的三项时，只修改该版本，标明与组标识的差异，不自动改其他文件、不自动拆组。

提供显式“用此版本更新分组标识”或“拆出为独立歌曲”；前者只更新 Song 的 Group 三项，不改其他版本标签。单版本歌曲产生同键 Song 时自动关联，手动拆分／撤销形成的例外除外。纯标签差异不证明实际音频变化；已知文件内容替换另按第 12 节处理。

## 9. 共享歌词与版本时间轴

SongLyrics 保留完整原文、原格式、翻译、发音、来源、Revision 和明确清空状态；不按去掉时间戳的可见文字判等。相同完整文档可以共用，不同文档在合并预览选择默认，未选项连同原来源／偏移／时间基准归档。

版本默认继承共享歌词，LyricsOffsetMs 属于版本。共享歌词编辑区明确标记影响整组；切换 Selected 不丢失默认歌词草稿。已有版本覆盖则显示其覆盖状态，覆盖编辑草稿随版本保存，不能隐式修改默认文档。

| 时间轴关系 | 处理 |
| --- | --- |
| 时间轴相同 | 共享文档，保留原版本用户偏移 |
| 全曲恒定差值 | 经确认的版本对齐偏移；符号沿用现有语义，用已知样本验证 |
| 漂移／变速／删段或未验证 | 不自动套偏移；保留版本文档覆盖，或将实际不同内容保持分开 |

旧偏移只能在时间基准不变时直接沿用。更换默认文档后，需要确认各版本的新偏移；无法确认时保留原文档覆盖，不能把旧 offset 直接附到另一时间轴。偏移记录绑定歌词基准和媒体修订；LRC 内 offset、版本 offset、播放器显示提前量分别处理，只应用一次。

播放加载共享歌词，但使用 ActualPlayingMusic 的偏移／覆盖；当前查看 MP3 的偏移修改不能影响正在播放 FLAC 的时间轴。共享默认文档修改会按修订刷新所有继承者，包括正在播放版本；刷新不新建媒体会话。

在线歌词请求按 Song＋查询内容／Revision 去重，侧车／内嵌读取仍带 MusicId。扫描到另一个文档只新增候选／归档，不覆盖已选默认或明确清空状态。迟到下载／翻译提交前检查 Song、成员、文档修订及请求代次。

导出／写入歌词时明确目标版本及基准／该版本时间轴，版本偏移最多烘焙一次；原文、翻译、发音一起保持时间基准。不会随用户单纯保存标签而自动写出共享歌词。

## 10. 合并、拆分、移除与撤销

### 10.1 统一合并预览

多选歌曲和“关联已有文件”进入同一服务。已经属于另一 Song 的文件不能静默转移；缺失／错误标签可以显式校正分组资料，但首版不能绕过真实跨专辑或已知 Remaster 边界。

预览包含：

- 参与的 Song／Music、三项匹配及内容差异、各文件 info／封面和可用状态，保留／拒绝选项。
- 保留哪个 SongId 及其 Group 三项；无需选择流派／作曲／年份等共享 info，也不统一各文件封面。
- 共享收藏 OR、收藏排序、默认歌词／归档／覆盖／偏移结果。
- 自动选版或保留哪个手动首选；当前查看版本与首选分别标记。
- 每个歌单原位置、固定版本／跟随 Song 的结果，是否折叠重复项（默认不折叠）。
- 当前播放／队列影响、待写文件任务、恢复资料；不进行文件删除、转码或自动写回。

收藏排序默认取原收藏显示序列最靠前的位置。不同 info 只展示差异，版本字段原样保留；年份／指挥等差异仍可说明候选实际不相同，不能仅因无需选共享值就忽略风险。

### 10.2 条件提交与失败

1. 取得不可变预览，捕获 Song、成员、歌词、受影响关系及待写任务的修订／比较值；预览期间不长期持有库锁。
2. 用户确认后取得 LibraryOperationGate，在短数据库事务内重新核对全部预期值。仅持有维护锁不足以替代收藏／歌词／远程扫描等独立写入者的条件检查。
3. 以操作 ID 幂等写入归档、归属、共享状态、歌单更新、别名／墓碑和完整操作记录；普通标签／技术参数／版本封面不搬移、不相互覆盖。
4. 事务失败全批回滚；事务成功即“已提交”，窗口关闭／取消等待不能报告为已撤销。
5. 成功后 UI 线程一次批量发布，保持当前实际 Music 对象、EntryId 和进度；失效未开始的预取和相关投影。UI 发布失败从数据库重建，不重复执行合并。
6. 维护租约→数据库事务的锁顺序固定；网络／文件 I/O 不在事务内。与 metadata gate 的顺序在 T0 固定，禁止反向嵌套。退出等待真实提交完成。

### 10.3 拆分与恢复

拆出版本建立新 SongId，Group 三项取该版本，保留所有版本标签／封面／偏移；复制当前共享收藏和适用歌词为独立快照。新 Song 默认自动模式。原手动首选若被移走则转回自动；其他首选不变。原组至少留一个版本，最后一个不提供拆分。

固定被拆版本的歌单／队列条目随版本更新 SongId；普通 Song 条目默认仍指向原组。操作快照明确记录的旧来源条目可以在恢复预览中提议还原；不猜测并复制所有后来加入的关系。当前播放不换文件，历史明细不改写。

“移除版本”默认仅从库解绑／保留必要墓碑，不删除物理文件。最后一个版本需明确选择保留缺失 Song 或移除歌曲共享状态，预览受影响的收藏、歌词和歌单。

一键撤销仅在相关成员／共享状态／关系与提交后快照一致时可用；有后续编辑、二次合并、拆分或新增关系则展示差异恢复。不能回灌旧快照覆盖新工作，不能回滚后续历史和已上报会话。重启根据持久提交状态恢复，不重复归组或发外部动作。

## 11. 歌单、浏览、统计和其他消费者

### 11.1 歌单与出现项

迁移保留所有 PlayListMusic.Id 和显示顺序，新增 SongId 及原 Music 来源信息。普通旧歌单条目默认跟随 Song；初始一对一不改变效果。合并时同一歌单含两个原版本，默认保留两个位置，并明确“两个位置默认都跟随自动／手动首选”；可逐项固定原版本。

折叠重复必须逐项预览，默认关闭；优先保留原显示顺序第一项，被移除关系进入操作快照。普通加入已有 Song 时提示已存在，并允许仍添加一次；批量新增可按 Song 去重输入，但不整理既有重复项。排序／删除／详情播放全部传关系 Id，不按 SongId 或 MusicId 批量误操作。

### 11.2 浏览和查询

全部歌曲、收藏、艺术家、推荐按 Song 展示；文件夹／来源文件视图仍列 Music。专辑按 GroupAlbum 分类，同一组的格式副本只占一个歌曲位置，普通播放用组内策略；原曲序冲突／有意重复收录必须在预览解决或保持独立，不能无提示丢掉收录位置。

列表的额外 info／封面／对应排序来自 DisplayVersion，详情来自 Selected，播放来自 Actual，均不跨版本补齐。查询快照包含分组／成员／首选／元数据修订及来源范围，后台只处理不可变值，UI 线程批量发布，避免旧异步排序覆盖新选择。

歌曲数按 Song、文件数与来源容量按版本；歌曲总时长若展示，按当前稳定代表版本求和并明确口径。自动播放回退不改变列表汇总。搜索命中某版本不自动把它设为首选；结果可提供“查看命中版本”。

### 11.3 历史、推荐、Last.fm、分析与导出

历史保留实际 MusicId 和当时元数据／媒体时长，SongIdAtPlay 只回填身份，不改写已发生快照。当前歌曲聚合按实际版本的当前归属／别名，可按版本展开；不同专辑的不同 Song 不再因标题／艺术家相同混成一个。历史明细与当前归组汇总的口径分开。

找不到 Music 的旧历史按原 MusicId 建历史归属／墓碑，不按同名归给现存歌曲。版本 PlayCount 不丢失，Song 累计按既定版本汇总；不以有保留期／达标规则的历史条数覆盖累计值。

推荐收藏／歌单偏好每个 Song 计一次，收听按真实会话聚合；版本声学向量不合并成“身份指纹”。推荐的额外标签输入采用稳定 DisplayVersion，首选变化使下次推荐输入修订失效；一次离线回退不放大训练权重或改变已发布推荐。

Last.fm 等外部正在播放／Scrobble 取实际确认会话的版本快照。详情切换、归组、拆分、变更首选不重新上报；归并收藏迁移不自动批量 love。新显式收藏操作按已有用户设置同步。

响度／频谱／音频特征／缓存按 MusicId＋资源验证信息或现有等效内容键管理，不移到 Song。转换、USB／Walkman、封面导出、歌词侧车、文件定位明确目标版本；Song 入口先展示实际解析版本，不默认处理所有关联文件。

## 12. 扫描、资源状态和文件写入

| 事件 | 行为 |
| --- | --- |
| 新扫描到文件 | 先建立 Music＋Song 身份，嵌入歌词提交后按索引自动关联，在批次发布 UI 前回填归属 |
| 完整成功扫描确认缺失 | 标 Missing／保留记录；共享收藏、歌词、歌单仍在 |
| 盘／网络源离线、权限拒绝、认证失败、扫描取消 | 不推断文件不存在，不批量删除 |
| 移除扫描根／WebDAV 来源 | 解绑或墓碑；保留共享状态和关系，缓存受租约和既定策略管理 |
| 缺失文件恢复／显式重新定位 | 验证资源／内容身份后恢复；不按同名随意接回 |
| 仅标签变更 | 更新该版本元数据／修订，保护未保存草稿；按第 8.3 节处理 Group 三项 |
| 同路径被其他音频替换 | 不无条件继承旧归属；旧版本墓碑，新内容建立版本／Song或进入待确认 |
| 清理缓存 | 仅清可重建资料，不能删权威歌词、操作归档或仍引用的封面原件 |

可用性区分未知、可用、离线、确认缺失、权限／认证问题、来源禁用／移除、损坏／不支持；完整缓存有效性独立。输出设备／模式不兼容只影响当前选版，不永久标记文件损坏，设备／模式变化后重算能力。

资源验证信息使用本地长度／mtime 等或远程 SourceId／Href／ETag／Modified／Length，名字避免与识曲指纹混同。这些只提供低成本变化线索，不能证明音频始终未变；已知疑似替换影响自动选版资格，按需复核，不把普通改标签直接当作新音频。

待写文件任务增加 MusicId、规范化路径、资源基线、请求修订和明确内容快照。执行前重新验证目标，路径被替换、重新导入或版本已转移时不能把旧任务写到新文件；必要时保留待确认而非丢弃。允许文件占用后重试，但用户后来切换所选版本／修改共享歌词不改变旧任务的授权快照。

数据库提交与物理写入的状态分开记录；文件写入成功不能因为随后的通知失败而声称已经回滚。扫描继续服从现有批次、取消和在途等待约定，后台属性／集合只在 UI 线程发布。关闭候选发现后不继续排队识别／I/O。

## 13. 无损迁移与兼容

迁移在数据库公开 WhenInitialized 前完成，扫描、旧歌词迁移、标签写队列和历史写入不得提前启动。定位真实 DbPath，核对 schema、空间和备份可写性，使用 SQLite 一致性备份或受控连接快照，不能只复制活跃主 .db 而遗漏 WAL。

建议在同目录新代库 MusicDatabase.song-v1.db 中迁移，只有完成标记及完整性检查通过后才使用；原库保留为升级前快照。旧二进制继续旧路径不会直接写新结构；降级只恢复旧快照，不承诺升级后新资料反向同步。

新代库事务顺序：

1. 创建 Song、映射、歌词／覆盖／归档、别名／操作记录和迁移状态；每个现存 Music 初始各建独立 Song，复制三项 Group 标识，PreferredMusicId=null。
2. 所有版本标签、ImageHash、音质、路径、偏移、PlayCount 原样保留，不生成共享 info 或合并封面。Music.Id 和身份记录不消失。
3. 收藏／收藏排序迁入各自 Song，保留所有歌单关系 Id／显示顺序及原版本来源；孤立关系可恢复则保留为不可用条目，不能静默丢弃。
4. 按现有 MusicLyricsV2／旧 MusicLyrics 迁移规则转入一对一默认文档，保留原格式、翻译、发音、诊断、明确清空及原偏移效果；以后归组才选择冲突文档。
5. 历史增加身份映射，缺失 Music 的按原 MusicId 建墓碑；条数、时长和快照不变。待写文件任务绑定可验证目标，无法验证的保留待确认。
6. 校验不变量、数量／顺序／资料摘要和数据库完整性，提交完成标记后才发布初始化成功。失败保留旧库，不公开半迁移状态。

旧库同路径重复数据库行需要先迁移引用，再保留冗余身份映射／墓碑；不能调用当前直接删除歌词的 DeletedMusicList 来清理。无法确认的冲突保存诊断并停止激活新库，不能猜测归属。

JSON PlayState 与 SQLite 不能同事务：版本化文件、临时写入后原子替换，新加载器同时读旧格式。旧 MusicId 在新库仍可映射，任意崩溃点可重试，升级第二次不得再增 Song、关系或归档副本。

验收断言：初始有效组一对一（历史墓碑／重复修复单独核算）；Music 身份及版本字段摘要保留；收藏等价；歌单关系／顺序不变；历史条数／时长不变；歌词全部可追溯；首选／固定版本合法；重复迁移幂等。

## 17. 当前交付：默认自动关联（2026-11-11）

用户明确要求：巨量曲库默认自动关联，手动入口用于处理例外。这一决定取代第 16 节及早期阶段“只生成候选”的行为。

### 17.1 规则及兼容性

- 标题、艺术家、专辑全部完整且相同即关联，包括不同格式和相同格式的重复文件。NFKC 兼容规范化、忽略大小写、折叠空白；长度前缀键避免标签分隔符碰撞。跨专辑、Live／Remaster 等仍在三项标签中的差异保持分开；空值和已知未知占位标签不参与。
- 该规则按用户选定的标签身份判定，不验证实际音频。只在文件名或未参与匹配的其他标签中标明 Remaster 的文件，三项一致时仍会关联，可手动拆出。不同年份、流派、曲目号、封面、时长和技术信息均保留于版本，不参与关联。
- 启动在曲库首次发布前处理所有已有独立组；已经使用 v1 版本功能的库同样升级，不要求删库或重新导入。v1 数据库在改动前在线备份为 `.autolink-v2.bak`，原始旧库及恢复记录保留。旧 v1 程序不能直接读取结构 v2；如需回退应使用升级前备份，避免覆盖升级后的编辑。
- 新增扫描批次／外部导入、远程标签读取、单版本歌曲标签保存和专辑标签编辑均在提交后处理关联；多版本组内的单个文件改标签不隐式拆组。文件缺失不取消组归属。
- 保留最早有效 Song 身份，收藏取并集、收藏顺序取最大值；保留目标组首选，为空时继承来源组的有效手动首选。默认选版策略不变，不切换正在播放的文件。
- 歌单关系 Id、顺序、重复位置和 RequestedMusicId 原样保留，仅更新 SongId；实际播放文件历史保留。
- 目标共享歌词已有内容或为用户明确清空时优先保留。目标只有空缺省时优先采用来源用户文档（包括明确清空），再采用首个非空来源。不同的非空文档／用户明确清空保存为版本覆盖，原来源、修订和诊断保留；空缺省继承共享文档，已有覆盖不覆盖。
- 拆出的新 Song 或撤销合并恢复的 Song 记录自动关联例外，重启和再次扫描不合回。升级时从旧 Split／Undo 日志恢复例外；显式手动合并可恢复参与自动关联。

### 17.2 实现与规模边界

- `SongAutoLink` 为每个 Song 保存规范化索引键与例外标记；`SongAutoLinkDirty` 由 Song 插入／三项标签变化的数据库触发器持久化，`SongAutoLinkPending` 保存待处理键。无唯一键约束，允许用户明确保留同标签的独立歌曲。
- 首次批量 SQL 建立独立组，不把全部 Music 文件实体装入内存；索引按 512 个变更项提交，歌词按 256 个候选批量读取／转换。后续无变更只检查空待办；不做全库两两比较，不逐歌执行异步往返或全库 UI 刷新。
- 每次处理 64 个候选键，同键的全部组在一个事务中归并并记录一次 AutoMerge 前后快照；失败全部回滚，待办仍在；取消在批次边界检查，可继续处理。自动调用由异步门串行化，事务重新验证成员、标签、文档和例外。
- 扫描先完成嵌入歌词入库、关联和本批次投影，再发布 UI；扫描完成统一刷新。增量曲库行按 Song 去重，底层仍保留每个文件。远程标签完成后统一重读归属，元数据保存发生关联时只刷新一次曲库；详情保留未保存草稿，干净文档重新读取所有者和修订。
- 恢复快照只包含受影响组，仍采用严格条件撤销；合并后有用户编辑时拒绝覆盖，可以手动拆出。极端单组含大量版本时快照大小随组大小增长；十万文件规模测试不等同于十万版本单组测试。
