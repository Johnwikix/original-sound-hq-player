# 空音乐库占位 UI + AddFolderPage MVVM 改造

## 任务一：MusicBrowsePage「完全无音乐」占位 UI

### 视觉设计（与 AddFolderPage / PlayListPage 空状态同一视觉语言）
- 占位只覆盖内容区（Row2），顶部标题 + SelectorBar 保留，布局稳定无跳变。
- `View\MusicBrowsePage\MusicBrowsePage.xaml` Row2 改为叠加 Grid：
  - 内层 `ContentFrame` 不变，占位可见时反向隐藏（页面新增静态函数 `InvertVisibility`，x:Bind 函数绑定，避免空子页残留表头/滚动条）。
  - 外层 `EmptyLibraryGrid`：`AllowDrop` 支持拖文件夹入库，结构完全复刻 AddFolderPage 空状态：
    - 96×96 `Border`（CornerRadius 28，`SubtleFillColorSecondaryBrush`）内嵌 44px Accent `FontIcon`，Glyph 用 **E8D6（MusicInfo）**，区别于文件夹页的 E8B7；
    - 标题 28px SemiBold（`MusicBrowseEmptyTitle`）、副标题 14px 次要色可换行（`MusicBrowseEmptySubtitle`）；
    - Accent 按钮：E8B7 图标 + 复用现有 `AddFolder.Text`，`Command` 绑定到 MusicBrowseViewModel；
    - 底部 12px 拖拽提示，复用现有 `AddFolderPageDragHint.Text`，Opacity 0.6。

### 状态与数据链路（MVVM）
- `ViewModel\AppViewModel.cs`：
  - 新增 `public Visibility EmptyLibraryVisibility { get; set => SetProperty(ref field, value); } = Visibility.Collapsed;`（与现有 `ProcessRingVisibility` 同风格）。
  - 在 `NotifySongsSourceChanged()`（L737，库变更唯一汇聚点，所有入库/删库路径必经）更新：`EmptyLibraryVisibility = SongsSource.Count == 0 ? Visible : Collapsed;`。初始 Collapsed，避免启动加载期间闪现。
- `ViewModel\Pages\MusicBrowseViewModel.cs` 新增两个 RelayCommand：
  - `EmptyAddFolderAsync`：显示 `ProcessRingVisibility` → `await App.Services.GetRequiredService<AddFolderViewModel>()` 的添加流程 → finally 隐藏。AddFolderViewModel 是 DI 单例，方法自包含，直接复用。
  - `DropFoldersFromEmptyAsync(folders)`：拖放入库，同样包 ProgressRing。
- `MusicBrowsePage.xaml.cs` 仅新增拖放三事件（DragOver 设 `AcceptedOperation.Link`、DragLeave、Drop 提取 StorageItems 转发 VM）——属"交互转发"，不含状态。

### 本地化（遵守 AGENTS.md）
- 仅用 x:Uid，不新增 GetString 调用。6 种语言（zh-CN/en/ja/de/es/ru）`Resources.resw` 各新增 2 键：
  - `MusicBrowseEmptyTitle.Text`：如 zh-CN「音乐库还是空的」/ en「Your library is empty」
  - `MusicBrowseEmptySubtitle.Text`：如 zh-CN「添加本地音乐文件夹，即可开始构建你的音乐库。」
- 按钮与拖拽提示复用现有键，不新增。

## 任务二：AddFolderPage code-behind → MVVM

### ViewModel（`ViewModel\Pages\AddFolderViewModel.cs`）
- 新增三个可见性状态属性（SetProperty，替代页面 UpdateState/ShowLoading/HideLoading）：`LoadingVisibility` / `EmptyVisibility` / `ListVisibility`。
- `LoadFoldersAsync` 末尾直接更新上述状态（防御性判断 `DispatcherQueue.HasThreadAccess`），删除 `FoldersLoaded` 事件（唯一订阅者是页面）。
- 命令化（[RelayCommand]）：
  - `AddFolderAsync`：现有 `AddFolderButton_Click` 逻辑 + loading 包裹，供本页按钮与 MusicBrowse 占位按钮共用；
  - `RescanFolderAsync(int folderId)`：迁入页面里的 `Task.Run(RescanFolder)`；
  - `RemoveFolderAsync(int folderId)`：内联 `DialogHelper.ShowConfirmAsync`（XamlRoot 取 `App.Services.GetRequiredService<MainPage>().XamlRoot`，与 MusicBrowseViewModel L665 同模式）+ 现有删除逻辑；
  - `OpenFolder(string folderPath)`：现有逻辑平移；
  - 公共 `DropFoldersAsync(IReadOnlyList<IStorageItem>)`：现有 Grid_Drop 逻辑 + loading 包裹。

### DataTemplate 内按钮（沿用项目既有 `MusicCommands` 模式）
- 新增 `Services\FolderCommands.cs` 静态命令类（`IRelayCommand<Folder>`），内部经 `App.Services` 解析 AddFolderViewModel 调用上述方法；
- `Model\Folder.cs` 增加透传属性（同 `Music.PlayCommand => MusicCommands.PlayCommand`）：`OpenFolderCommand` / `RescanFolderCommand` / `RemoveFolderCommand`；
- 模板内三个按钮改为 `Command="{x:Bind RescanFolderCommand}" CommandParameter="{x:Bind}"`。

### View（`View\AddFolderPage.xaml` / `.cs`）
- 三层 Grid（LoadingGrid/EmptyGrid/AddFolderGrid）Visibility 改 `x:Bind ViewModel.XxxVisibility, Mode=OneWay`；
- 顶层两个按钮改 `Command="{x:Bind ViewModel.AddFolderCommand}"`；
- code-behind 删除：`OnFoldersLoaded`、`UpdateState`、`ShowLoading/HideLoading`、全部 Click 处理器、`RemoveFolder`、`_musicDatabaseService` 字段；仅保留构造函数与拖放三事件（DropOverlay 显隐属瞬时视觉反馈，留在视图层）。

## 验证
1. `dotnet build` 编译通过；
2. 静态核对 6 语言 resw 新键齐全、键名一致（AGENTS.md 要求）；
3. 手动场景：空库首启显示占位 → 添加文件夹后消失 → 删除全部文件夹后重现；占位上点按钮直接弹选择器；拖文件夹到占位可入库；MusicBrowsePage 标签切换不受影响。
