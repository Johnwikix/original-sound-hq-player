桌面歌词 Win2D 逐字渲染薄宿主(CanvasLyricsRenderer)实现计划

## 设计要点(基于已验证事实)
- **绕开 coordinator,直接组装内部件**:LyricsRenderCoordinator 与静态总线的耦合全部在其 Attach()/私有 _cached* 字段;而 RenderLyricsLine / LyricsLineRenderer / LyricsLayoutManager / LyricsSynchronizer / LyricsAnimator 对总线**零静态依赖**(已逐一 grep 验证),全部参数注入,可原样复用。
- **单行形态**:只实例化/布局当前一行(+翻译),垂直居中;整页滚动的滚动/渐隐/悬停/点击代码全部跳过。
- **样式独立**:只吃 DesktopLyricsStyle(7 字段),不碰主界面 LyricsSettingsBus。
- **宿主**:代码内直接 new 裸 CanvasAnimatedControl(主工程已引用 Win2D 1.4.0),事件接线照抄 AdvanceLyricsCanvasControl L126-169 去掉指针五件套;spectrum 已验证穿透窗口内 Win2D 渲染无问题。
- **开关**:设置页新增"桌面歌词逐字效果"ToggleSwitch(默认关,跟随主界面 EnableAdvancedLyricsEffect=false 先例);关=现有 TextBlockLyricsRenderer,开=新 CanvasLyricsRenderer,窗口内热切换。

## 新文件(仅 1 个)
**`DesktopLyrics/CanvasLyricsRenderer.cs`**(~300 行,纯代码无 XAML),实现 IDesktopLyricsRenderer:

1. Content:直接返回 CanvasAnimatedControl(ClearColor=Transparent,TargetElapsedTime=1/60)。
2. Canvas 事件接线(CreateResources→置布局脏;Update→OnCanvasUpdate;Draw→ds.Clear(Transparent)+OnCanvasDraw;SizeChanged→脏标记+Invalidate),照抄 AdvanceLyricsCanvasControl 但不含指针事件。
3. 数据通道复用现有 Set*(窗口已转发 4 条总线,零改动):SetLyrics 存 List<LyricLine> 引用并重置选行;SetPlaybackTime/SetOffset/SetIsPlaying 更新缓存。
4. OnCanvasUpdate(核心 ~100 行,逻辑照抄 coordinator L385-424):
   - 时间平滑:播放中内部时钟按 args.Timing.ElapsedTime 自增,与外部时间差 >250ms 硬同步;暂停时直接跟外部;currentTime = internal − offset。
   - 选行:LyricsSynchronizer.GetCurrentLineIndex(currentTimeMs, lyrics)(纯时间判定,不用 IsCurrent)。
   - 切行/样式/尺寸变化时在 Update 回调内重建当前行:new RenderLyricsLine → LoadFromLyricLine(line, line.EndMs)(与 coordinator L272 一致)→ LyricsLayoutManager.MeasureAndArrange 单元素列表(参数见映射表)→ 旧行 DisposeTextLayout/DisposeTextGeometry/DisposeCaches。
   - LyricsAnimator.UpdateLines 单行列表驱动透明度过渡(Played=1.0、Unplayed=0.5、Secondary=0.6),line.Update(elapsed) 推进。
5. OnCanvasDraw:line.EnsureCaches(sender, strokeWidth)(惰性);按 coordinator L619-622 写 UnplayedFillTint;按 L628-635 设置 LyricsLineRenderer 七属性(IsPlaying=line.GetIsPlaying(ms)、CurrentProgressMs、Line、Played/UnplayedFillColor=Style.Color、Glow/Scale/Float=false);单行块垂直居中经 ds.Transform 平移(coordinator 的滚动定位跳过);Draw 后还原 Transform。
6. 降级:LRC 纯文本行 IsPrimaryHasRealSyllableInfo=false 时内部件自动走整行渐进填充(DrawFullLineRegion),无需额外分支。
7. 健壮性:设备丢失 catch(ObjectDisposedException)→ DisposeCaches 下帧重建(coordinator L361-365 同款);Dispose 释放当前行缓存。
8. v1 明确不做(参数位保留,后续可加):发光/模糊/浮动/缩放、边缘渐隐、滚动、点击 seek。

## 样式映射表(DesktopLyricsStyle → 内部件)
| DesktopLyricsStyle | 内部件参数 |
|---|---|
| FontSize | originalFontSize(翻译行=×0.7,与现文本渲染器一致) |
| ShowTranslation=false | translatedFontSize 传 0(RenderLyricsLine 不建 SecondaryTextLayout,翻译含描边整体隐藏) |
| FontFamily(空→"Segoe UI") | fontFamily |
| Color | Played/UnplayedFillColor 同色;未播放可见度靠 UnplayedOpacity=0.5(主界面默认行为) |

| FontWeight | fontWeight |
| (固定 0.6) | 翻译行 SecondaryOpacity,与现文本渲染器 _transOpacity 一致 |

## 验证
1. KRC/QRC 逐字歌:开开关→单行逐字扫光,字号/字体/颜色/描边/翻译行与桌面歌词设置一致;锁定/解锁、拖动、悬停按钮、点击穿透均不受影响。
2. LRC 纯文本歌:整行渐进填充降级正常,无逐字扫描。
3. 关开关→即回文本渲染器;暂停→逐字停住、恢复→继续;拖动进度/调整偏移/切歌跟随正确。
4. 边界:描边宽度 0~6、字号 10~200、描边开/关、翻译开/关组合;主界面高级歌词同时开启时两渲染器互不干扰(独立实例、独立样式)。
5. 全量编译 0 错误;关开关回归验证现有文本渲染器行为不变。
