# 外部文件一次性播放（文件关联 + 打开方式入口）

## 结论性设计

当前项目为 MSIX 打包（`EnableMsixTooling`）、单实例用命名 Mutex + 注册表 HWND + `WM_SHOWME`（不传数据）、播放链路以 `IsPlaybackEngineReady` 为守卫。参考项目 TheUntamedMusicPlayer 的实现可借鉴 manifest 声明与 `GetActivatedEventArgs()` 模式，但其 `Task.Delay(500)` 脆弱时序、无单实例转发、覆盖用户播放队列、静默失败等缺陷全部规避。未获用户答复的两个产品决策按默认执行：**曲终播完即停**（单曲循环模式仍重播该文件）、**失败时 Toast 提示**。

行为定义（按用户需求）：
- 双击/打开方式启动 → 后台解析文件元数据 → 只替换 `CurrentPlayingMusic` 并立即播放；**不**写入 `SequentialPlayingList`/`CurrentPlayingList`，**不**写数据库、不写播放统计。
- 已运行时再次打开文件 → 第二实例通过 `WM_COPYDATA` 把路径转发给现有实例（复用现有 HWND 通道），现有实例替换当前播放并显示窗口。
- 曲终：一次性曲目播完调用 `MusicEnd()` 停止；手动点"下一首"仍进入库列表播放（现状行为，`GetCurrentIndex()==-1 → nextIndex=0`）。

## 修改清单

### 1. `Package.appxmanifest` — 注册文件关联
在 `<Extensions>`（L61-65）内新增 `uap:Extension Category="windows.fileTypeAssociation"`，`DisplayName` 用 `ms-resource:AppMainTitle`，`SupportedFileTypes` 列 15 种扩展名，与 `ToolUtils.MusicExtensions`（`Utils/ToolUtils.cs:602`）严格一致：`.mp3 .wav .flac .wma .aac .ogg .oga .aiff .aif .m4a .dsf .dff .ape .opus .wv`。MSIX 部署后应用自动出现在"打开方式"候选列表。

### 2. 新建 `Services/OneShotPlaybackService.cs` — 一次性播放唯一状态源（DI 单例）
- `static string? CaptureActivationPath()`：先试 `Microsoft.Windows.AppLifecycle.AppInstance.GetCurrent().GetActivatedEventArgs()`，`Kind == ExtendedActivationKind.File` 时把 `Data` 强转 `IFileActivatedEventArgs` 取 `Files` 中第一个 `IsMusicFile` 且 `Path` 非空项；兜底解析 `Environment.GetCommandLineArgs()` 过滤音乐扩展名且 `File.Exists` 的参数（覆盖 unpackaged F5 调试）。
- `Begin(path)`：冷启动在 `OnLaunched` 最早调用——锁内置 pending 路径并立即 `Task.Run` 启动解析（`StorageFile.GetFileFromPathAsync` + 复用 `ToolUtils.GetMusicInfo`，`Utils/ToolUtils.cs:944`），得到的 `Music` 置 `IsOneShot=true`、`Id` 保持 0。解析任务暴露给引擎轨。
- `PlayNow(path)`：暖启动（WndProc 收到路径）调用——引擎已就绪则解析后到 UI 线程走 `MusicBrowseViewModel.PlayMusic(music)`（该路径 `IsChangeList:false` 本就不改列表）；未就绪则存 pending，由引擎轨稍后统一处理（事件驱动，替代参考项目的 `Task.Delay(500)` 启发式）。
- `OnEngineReadyAsync(ct)`：由引擎轨在 `UpdatePlaybackEngineReady()` 之后调用——await 解析任务（用 `StoppingToken` 包裹），成功则 UI 线程 `PlayMusic`；失败/取消则记日志 + `NotificationService.SendNotification` Toast，不影响引擎初始化本身。锁保护 pending 与解析任务的替换/取消，竞态安全、迟到回调检查生命周期。

### 3. `App.xaml.cs`
- DI 注册 `services.AddSingleton<OneShotPlaybackService>()`。
- `OnLaunched`（L225）第一行（mutex 检查前）调用 `CaptureActivationPath()`；第二实例分支把路径传给 `ActivateExistingInstance(path)`；第一实例在 `await _host.StartAsync()` 前调用 `Begin(path)`（解析与 Host 启动、IPC、DB 完全并行）。不重写 `OnActivated`（WinUI3 中 `OnLaunched` 总会触发，统一用 `GetActivatedEventArgs` 判别，避免双处理）。

### 4. `Helper/SingleInstanceHelper.cs` — 路径转发
`ActivateExistingInstance` 增加 `string?` 参数：HWND 有效时用现有 `WindowHelper.SendMessage`（`Helper/WindowHelper.cs:39`）发送 `WM_COPYDATA (0x004A)`，`COPYDATASTRUCT` 带 `dwData` 魔数 + UTF-16 路径（`Marshal.AllocHGlobal`/`UnicodeStringToHGlobal`，try/finally 释放）；随后保留现有前台/恢复/`WM_SHOWME` 逻辑。HWND 失效时维持现状（仅尝试激活）。

### 5. `MainWindow.xaml.cs` — 接收转发
`NewWindowProc`（L203）新增 `WM_COPYDATA` 分支：校验魔数、按 `cbData` 读 UTF-16 路径（异常安全），`DispatcherQueue` 上调 `OneShotPlaybackService.PlayNow(path)` 并复用/抽取 `WM_SHOWME` 的显示逻辑（不可见时 `Show()` + `InitializeTaskbarHelper()`）。

### 6. `Services/StartupCoordinator.cs` — 引擎轨整合（打开速度关键点）
`InitializePlaybackEngineAsync`（L131）中 `Task.WhenAll(...)` 完成后：若一次性解析任务已完成且成功，用外部 `Music` 替代 `AppViewModel.CurrentPlayingMusic` 调 `ipcService.InitializeMusic(...)`（内核首推直接加载外部文件，省一次旧曲加载）；否则照旧推恢复曲。`UpdatePlaybackEngineReady()` 之后追加 `await oneShot.OnEngineReadyAsync()`（解析未完成就等它，完成即播，全程不阻塞主界面显示）。

### 7. 曲终与数据保护（一次性语义落点）
- `Model/Music.cs`：加 `public bool IsOneShot { get; set; }`。
- `Services/BassPlayerCommandService.cs` `AutoPlayNextTrack`（L89）开头：当前曲 `IsOneShot` 时——`SingleLoop` 重播该文件，其余模式 `MusicEnd()` 停止，return。
- `Services/PlaybackStatsService.cs` `StartSession`（L70）：`music is null || music.Id <= 0` 直接 return（未入库曲目不产生统计会话，单点守卫覆盖所有入口）。
- `Services/PlaybackStatePersistence.cs`（L111）：`LastPlayedMusicId` 仅在 `CurrentPlayingMusic.Id > 0` 时写入，否则沿用 `existing.LastPlayedMusicId`，避免外部文件把下次启动的当前曲恢复清空。

### 8. 本地化 + 记录
- `Strings/{de,en,es,ja,ru,zh-CN}/Resources.resw` 各新增独立键（无属性后缀，符合 AGENTS.md 约定）：`OneShotOpenFailedTitle`、`OneShotOpenFailedContent`（内容含文件名与原因），经 `ToolUtils.GetString` 取用（用法同 `MusicDatabaseService.Metadata.cs:75`）。
- `docs/Changelog.md` 顶部追加条目（文件 + 改动一行式）。
