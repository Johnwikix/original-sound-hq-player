## 问题
旋转网格（RotatingMesh）背景着色器存在不易察觉的色阶断裂（banding）。

## 根因（已在代码中定位）
4-pass 管线中有三个 **8bit 中间渲染目标**，色带在中间 pass 就被"烧"进纹理：

```
封面(8bit) → Rotation → _rotationTarget(1/8分辨率, 8bit)
           → 高斯模糊σ=21.25 → _blurTarget(1/8分辨率, 8bit)
           → 双线性上采样 → _upscaledTarget(全屏, 8bit)
           → 合成pass(饱和度×1.3 + ±0.5LSB抖动) → 8bit bgCache
```

- 模糊后的图像是极平滑的低频渐变，相邻纹素真实差远小于 1/255，写入 8bit `_blurTarget` 时量化成 1-LSB 台阶；上采样 ×8 后变成约 8px 宽的色带并再次量化。
- 合成 pass 已有的 IGN 抖动（`ditherStrength:1` = 标准半 LSB 配置，RotatingMeshCompositeEffect.cs:143）只能消除最终输出的量化，无法消除中间纹理里已量化的台阶；`ApplySaturation(1.3)`（:98）还会把台阶对比放大 1.3 倍。
- 求解目标 `_solveTarget` 已是 RGBA32F，无需处理；其余 6 个背景着色器均为单 pass 且自带较强抖动，不涉及。

## 修复（最小改动，只动一个文件）
`External\AnimatedWin2dControls\AnimatedWin2dControls\Renderer\Background\RotatingMeshBackgroundRenderer.cs` 的 `EnsureTargets`：

1. `_rotationTarget`、`_blurTarget`（1/8 分辨率，内存可忽略）与 `_upscaledTarget`（全屏）改用 `DirectXPixelFormat.R16G16B16A16Float` + `CanvasAlphaMode.Premultiplied`（显式 DPI 的构造重载，DPI 语义与现状一致）。FP16 在值 ≤1 时精度约 1/2048 ≈ 0.125 LSB，中间量化彻底消失。
2. FP16 创建包 try/catch，失败（罕见老设备）回退现有 8bit 默认格式，与现状行为一致（沿用 `_solveTarget` 的防御模式）。
3. 其余一律不动：DPI 逻辑、BlurAmount、ditherStrength=1、Clamp(0.07,0.97)（原版设计常量）、三个着色器本体零改动。
4. 更新相关注释，记录 banding 根因与 FP16 依据。

内存影响：全屏 FP16 ≈ 8B/px（1440p ≈ 29MB、4K ≈ 66MB），两个 1/8 分辨率目标合计 < 1MB，可接受。

否决的替代方案：把低分辨率 FP16 模糊图直接绑给合成 pass 在 shader 内上采样（省全屏目标 + 一趟全屏 pass）。因需改 `_blurTarget` 的 DPI，会牵动高斯模糊 DIP 语义与 ComputeSharp DPI 补偿节点（代码中已有三处注释记录该雷区），风险收益不匹配，不做。

## 验证
1. `dotnet build` AnimatedWin2dControls 与主项目，0 错误。
2. 运行应用 → 设置选"旋转网格"，用平滑渐变封面的歌，暗/浅色主题各观察一次，与修改前对比色带是否消失。
3. 回归检查：换歌交叉淡化、窗口缩放/跨屏（DPI 重建路径）、无封面调色板兜底、网格创建失败时的模糊背景回退路径。
