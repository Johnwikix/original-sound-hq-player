# 2026-11-07

## 文件夹页目录树展开/收起过渡
- `View/Controls/TreeViewExpansionMotion.cs`：**最终形态只做位移补间**。展开/收起前给所有 `ItemsStackPanel` 里已生成的行挂 `Visual.Offset` 隐式动画（180ms），180+80ms 后用 `DispatcherQueueTimer` 摘除。新行本身不做任何动画。
- **TreeView 的行级入场动画在框架外做不了**，四种方案全部被否决（都实测过，别再试）：
  1. `Composition` 在 `Expanding`/`LayoutUpdated` 设 `Visual.Opacity`：容器首帧由框架绘制，此时 `GetElementVisual` 拿到的视觉还没接入渲染树，设 0 被忽略 → 先全亮一帧再暗下去（闪烁）。
  2. XAML `Storyboard` 驱动内容元素 `Opacity`：同样晚一步；且绑定值恢复（`RevealOpacity = 1`）会覆盖动画，两帧之间露全亮。
  3. `TreeView.ItemContainerTransitions` 加 `EntranceThemeTransition`（含/不含 `AddDeleteThemeTransition`）：入场能生效，但**树重建时的选择恢复用例超时**（`CheckSiblingSelectionAsync` 的 `Wait` 不满足），必须放弃。
  4. 内容元素默认 `Opacity="0"` + 行 `Loaded` 按节点状态淡入：绑定求值晚于首帧、**容器复用时 `Loaded` 不再触发**，导致行永久不可见（复现「子目录消失」）。已回退。
- **结论**：行容器首帧与复用时机都在框架内部，外部无法安全干预。要做逐行/整批淡入必须替换 `TreeViewItem` 的容器模板（自带内层容器，对内容做透明度），代价是要重跑选中/拖拽/缩进那几组用例。
- 收起方向：WinUI 在 `Collapsed` 之前**同步**移除子行；同帧把 `IsExpanded` 设回 true 也不恢复容器（实测 `collapsed` 触发、`expanding` 不触发、`ContainerFromItem` 仍为 null）。只能让剩余行补间上去。
- 关键结论：`Composition` 属性读取不反映动画值，但 `TransformToVisual` 会计入合成位移；行是否绘制用「行区域平均亮度 vs 纯背景 96.0」判定。**采样展开瞬间必须排除「父行还占着子行目标位置」的帧**，否则会把父行亮度当成子行，误判成「先亮后暗」。
- 验证：主工程 Debug/x64 通过；`_tools/FolderBrowserUiRegression` 75 项全通过（连续三次一致）。
